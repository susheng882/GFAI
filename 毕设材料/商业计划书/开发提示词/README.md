# GFLC 开发提示词资产 · 使用说明

这套文件是给 **后续开发** 用的 AI 提示词资产，把《产品报告》《技术报告》《学术图表册》里的真实规格，压缩成 AI 编码助手能直接执行的两层提示词。

## 文件构成

| 文件 | 作用 | 用法 |
|---|---|---|
| `01_系统提示词.md` | **项目级常驻提示词**：项目身份、技术栈硬约束、**11 条架构铁律**、数据模型、AI 管线（取材/归一化/切片/七类任务/契约/降级/索引维护）、幻觉治理、成本护栏、38 项功能总账、**完整目录树 + 环境变量 + 常用命令**、G1–G7 门禁与指标口径、视觉规范、诚实边界、启动自检 | 整段粘贴为 system prompt，或存为 `.cursorrules` / `CLAUDE.md`，**每次会话都加载** |
| `02_开发任务提示词.md` | **任务级提示词库**：前置约定（API 契约与错误码 / 真实 Prompt 模板 / 行为约束三档）+ 5 个通用模板 + P0–P6 阶段 + 8 个模块 + 答辩演示模板 + 交付自查清单 | 做具体任务时，复制对应模板，替换 `{占位符}` 后发给 AI |
| `README.md` | 本说明 | — |

## 推荐使用顺序

1. **先加载 `01_系统提示词.md`**（常驻规则）——它保证 AI 始终知道「这个项目不许做什么、必须做什么」。
2. **开工前读 `02` 的「前置约定」**：API 契约与错误码、已定稿的 Prompt 模板、行为约束三档，这三样决定接口与拦截的一致性。
3. **按当前阶段/模块选任务提示词**：刚开工用 `P0`；做某功能用对应模块提示词；临时的活用通用模板 A–E。
4. **交付前**对照 `02` 末尾「交付自查清单」八条过一遍；答辩前用 `模板 F–H` 准备演示与口径核对。

## 一个最小示例

> 你想让 AI 实现「PDF 上传后解析并生成卡片」：
>
> 1. system prompt 用 `01_系统提示词.md`；
> 2. 任务提示词复制 `02` 的 **模板 B（Worker 任务）+ 模块 3（PDF 与卡片）**，补一句「本次只做上传 + 切块 + 卡片生成，不做复习排程」；
> 3. 用 **约定 1** 定义接口响应与错误码，用 **约定 2** 的卡片 Prompt 模板；
> 4. AI 产出后用 **模板 D** 补契约测试与越权测试；
> 5. 用「交付自查清单」验收。

## 三个关键约定（务必守住）

1. **三态标注**：功能必须区分【已实现】/【已设计】/【已规划】，绝不把「已设计」说成「已实现」。父子块、重排目前是【已设计·未实现】。
2. **架构铁律不可破**：CPU 密集任务不进 API、大文件走预签名直传、Redis 只存小状态、向量走 pgvector 同库、失败禁止静默、权限过滤在召回阶段做。
3. **数字以材料为准**：本项目已修正过多处历史口径（团体授权 900 元/年、盈亏平衡约 10 人、2027 研考人数未公布、三容器、轻/中/强档等），提示词里已固化正确值，**不要用旧值**。

## 与项目材料的关系

- 提示词是「执行层摘要」，材料是「事实来源」。两者冲突时，**以 `产品报告` 与 `技术报告` 正文为准**。
- 若材料更新（版本升级、数字调整），只需同步修改 `01` 第十二节「诚实边界」与 `02` 模板 H 里的关键数字，不必重写全文。
- 当前对应 **V2.0 口径**。

## 维护约定

- `01` 是所有会话的地基，改一处要检查是否影响其他章节。
- `02` 可按进展增补模板，保持「目标→输入输出→约束→验收→禁止」五段式。
- **注意：本套文件当前在 `开发提示词/` 与 `毕设材料/商业计划书/开发提示词/` 各有一份，内容应保持一致。修改后请同步两处，或只保留一份以免不同步。**
