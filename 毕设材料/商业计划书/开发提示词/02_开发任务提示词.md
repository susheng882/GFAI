# GFLC 开发任务提示词库（Development Prompts）

> **用法**：先加载 `01_系统提示词.md` 作为常驻 system prompt，然后按当前要做的阶段/模块，从本文件复制对应的任务提示词，把 `{占位符}` 替换成实际情况，发给 AI 编码助手。
> 每条提示词都已内置：**目标 → 输入输出 → 硬约束 → 验收标准 → 禁止事项**。这是本项目「可交付」的保证。

## 前置约定（动手前先确认）

### 约定 1 · API 契约与错误码（所有端点共用）

**统一响应包裹**
```json
// 成功
{ "ok": true, "data": { }, "request_id": "req_xxx" }
// 失败
{ "ok": false, "error": { "code": "PARSE-002", "message": "PDF 文本层为空，已转 OCR" }, "request_id": "req_xxx" }
```

**异步任务统一**
```json
// 创建类接口立即返回
{ "ok": true, "data": { "task_id": "task_xxx", "status": "pending" } }
// 查询进度 GET /api/tasks/{task_id}
{ "ok": true, "data": { "status": "parsing|ready|failed", "progress": 0, "error": null } }
```

**错误码（域-编号，便于排障）**

| 错误码 | 含义 |
|---|---|
| `AUTH-401` / `AUTH-403` | 未登录或会话失效 / 越权访问 |
| `PARSE-001/002/003` | 文件不可读 / 暂无可抽取文本 / 切分失败 |
| `AI-001/002/003/004` | 模型超时 / 引用缺失 / 契约校验失败 / 分数低于阈值拒答 |
| `QUOTA-001/002` | 超日配额 / 超单任务上限 |
| `FILE-001/002` | 超体积上限 / 格式不在白名单 |

### 约定 2 · 真实 Prompt 模板（材料已定稿，直接套用）

> 这两个是《产品报告》第六章已定稿的模板原文，落地时以此为准，不要自由发挥。

**卡片生成（轻档）**
```
你是学习卡片生成助手。请根据以下知识点生成 3 张背诵卡片，每张包含问题、答案与知识点标签；
要求问题简洁、答案准确、可在原文定位、不输出多余解释。
输入：{chunk_text}
输出 JSON：{"cards":[{"question":"","answer":"","tag":"","page":0}]}
```

**题目解析（强档，五段缺一即失败）**
```
你是解题助手。请按「考点分析 / 解题思路 / 详细步骤 / 易错点 / 最终答案」五个部分输出解析，
缺任一段视为失败。题目：{question}；选项：{options}；参考答案：{answer}
输出 JSON：{"analysis":{"point":"","approach":"","steps":[],"pitfalls":[],"answer":""}}
```

> 变量用占位符声明、后端渲染；模板纳入版本库，任何变更须先在评测集上跑回归再上线。

### 约定 3 · 行为约束三档（哪些操作要拦）

- **无需确认即可执行**：格式整理、摘要生成、卡片生成
- **需用户确认后执行**：覆盖已有笔记、批量替换学习计划、删除学习记录
- **任何情况下禁止**：绕过权限读取他人资料、把用户文档用于模型训练、缺乏原文依据时编造答案

> 第三类是底线，必须在**代码层 + 提示层双重拦截**，不能只依赖模型自觉。

## 零、通用任务提示词模板（最常用）

### 模板 A · 新增一个 API 端点
```
在 GFLC 后端新增一个端点。

【功能】{一句话说明这个接口干什么，属于哪条主路径}
【方法与路径】{GET/POST} /api/{资源}
【鉴权】需要登录用户（HttpOnly Cookie），做行级权限过滤：只能访问当前用户自己的数据
【请求体】{字段:类型:约束}
【响应体】{字段:类型}（全部返回 Pydantic 模型）
【业务规则】{关键逻辑，如配额扣减、状态机流转}
【实现要求】
- 按 routers / crud / services 三层拆分：
  - router 只做参数接收、鉴权、响应组装
  - crud 只做数据库读写
  - service 承接业务逻辑（禁止跨层）
- 同步边界只放短查询；任何耗时操作写成任务投递给 Redis 队列，立即返回 task_id
- 失败统一返回 {code, message}，错误码可追溯，禁止 except: pass
- 写单元测试：正常路径 + 越权访问 + 参数非法 三类
【验收】{对应具体标准，如响应 P95 < 300ms、越权返回 403}
```

### 模板 B · 新增一个 Worker 长任务
```
在 GFLC 的 Worker 进程新增一个异步任务。

【任务类型】{如 video_transcribe / pdf_parse / question_parse}
【触发方】API 收到请求后写 tasks 表并向 Redis 队列投递，本任务由 Worker 消费
【输入】{依赖的数据，如 document_id、参数}
【处理步骤】
1. {步骤一}
2. {步骤二，含 AI 调用与契约校验}
3. 产物落 MinIO，元数据落库
【状态与进度】按 待解析→解析中→就绪/失败 四态回写；每步更新进度百分比
【断点续传】每完成一个可恢复单元写检查点；失败重跑从检查点续，不重复计费
【失败处置】记录错误码 + 人可读原因；已完成的段不丢弃；对应四级降级中的第 {n} 级
【幂等】用 document 内容哈希去重，同一文件重复上传复用已有结果
【验收】{如 50 页 PDF P95 ≤ 60s，解析成功率 ≥ 90%}
```

### 模板 C · 新增一个 AI 任务（Prompt + 契约）
```
为 GFLC 新增一个 AI 任务。

【任务】{类型}，落在 {轻/中/强} 档模型
【输入】{输入内容与预处理，如去除口语词、按 300 字切块}
【输出契约】输出 JSON，Schema 如下：
{ 字段:类型:约束 }
用 Pydantic 校验；引用字段必填（带来源块编号/页码/时间戳）
【Prompt 要求】
- 角色设定：{一句话}
- 必须标注每个结论的来源编号
- 输出前自检格式，不输出多余解释
【校验与降级】
- Schema 不通过 → 纠正性重试一次（回传报错，只修错不重写）
- 二次失败 → 标记该块失败并跳过；走第 {n} 级降级（模板/规则兜底）
- 引用缺失 → 判不合格，触发重试
【成本护栏】单任务 token 上限 {n}；命中缓存直接复用
【评测】用现有评测集跑：字段完整率 ≥ 95%、卡片可用率 ≥ 85%、五段完整率 ≥ 90%
【禁止】编造来源中不存在的数字/专有名词；输出非 JSON；超长截断不报错
```

### 模板 D · 写测试
```
为 {模块} 补齐测试。

- 单元测试：{核心函数，如切块规则/计分/成本计算}，行覆盖 ≥ 70%
- 契约测试：{AI 任务输出}，正常 + 缺字段 + 引用越界 三种用例
- 集成测试：{上传→解析→入库} 全链路
- 端到端：{四条主路径之二：视频→笔记→卡片} 用户视角走通
- 越权测试：用户 A 不能访问用户 B 的资料
用 pytest；测试数据用固定 fixture，不依赖真实外部 API（用 mock 适配器）
```

### 模板 E · 排查/修复一个缺陷
```
【现象】{用户看到什么}
【复现】{步骤}
【定位信息】{错误码 / 日志片段 / 任务 ID}
【要求】
1. 先定位根因（是路由层、服务层、Worker、AI 契约、还是数据层）
2. 给出最小修复，不顺手重构无关代码
3. 若涉及 AI 输出，检查是否属于四类失败（结构缺失/引用幻觉/粒度失当/格式错乱）
4. 补一条回归测试防复发
5. 说明是否需要重跑受影响的存量数据
【禁止】用 try/except 吞掉异常掩盖问题
```

## 一、分阶段开发提示词（按 16 周排期）

### P0 · W1–W3 立项与技术验证
```
进入 P0 阶段：技术选型、三通道 POC、成本基线、数据模型设计。

交付：
1. docker-compose.yml：nginx / app / data 三容器，app 内 API 与 Worker 分进程
2. Alembic 初始化 + 核心表迁移（users/documents/tasks/chunks/vectors/cards/questions）
3. 三条链路各跑通 10 个样本的 POC：
   - PDF：PyMuPDF 文本抽取 → 按标题切块 → 300 字块/100 重叠
   - 视频：平台字幕 → faster-whisper 转写 → 关键帧抽取
   - 题库：Excel/PDF 导入 → 题干/选项/答案结构化
4. 成本基线表：按真实单价记录每类任务单次成本
出口标准：三链路各 10 样本跑通，单任务成本符合预算（PDF ≤ 0.12、视频 ≤ 0.40）
```

### P1 · W4–W6 内容管线
```
进入 P1 阶段：PDF 与题库解析、语义切片、知识点抽取、卡片生成。

实现顺序（先结构化后多模态，先易后难）：
1. PDF 解析服务：文本层优先 + 版面块；扫描页回退 OCR 并标置信度
2. 语义切片：标题→段落→表格/代码块；超 800 字二次切；块 300 字、重叠 100、父块 1200
3. 知识点抽取（中档模型）：输出 单元类型/标题/正文/公式LaTeX/考点标签/难度/来源定位
4. 卡片生成（轻档模型）：问答卡 + 填空卡，每块 1 知识点，带溯源
5. 契约校验：JSON Schema + Pydantic；失败纠正性重试一次
出口标准：文字版 PDF 抽取 F1 ≥ 0.85，卡片可用率 ≥ 85%
```

### P2 · W7–W9 学习闭环
```
进入 P2 阶段：仪表盘、复习调度、刷题、错题本。

1. 可拖拽仪表盘：卡片拖拽/缩放（1×1、2×1、2×2）/隐藏/重置，布局自动保存
2. 复习排程：R1–R4 = 1/3/7/14 天；掌握度 m（0–1）驱动，低于阈值触发回炉
3. 刷题：按知识点/难度/题型组卷 → 在线答题 → 自动记错题
4. 错题本：错题沉淀 + 来源 + 错误归因；错题回炉再生成
5. 掌握度模型：作答结果/耗时/提示次数/要点覆盖/时间衰减 加权
出口标准：连续 7 天使用不出现阻断性缺陷
注意：排程与掌握度是【已设计】，需在此阶段落地为【已实现】
```

### P3 · W10–W11 视频链路
```
进入 P3 阶段：链接解析与上传、字幕与章节切分、时间锚点笔记。

1. 素材归一化三通道：平台字幕 / 语音识别 / 关键帧画面文字，时间轴对齐同一锚点
2. 三级取材降本：命中平台字幕即跳过下载与转写
3. 章节切分：边界误差 ≤ 30 秒；三类笔记（文稿/大纲/图文）
4. 时间锚点：每条笔记带可跳转时间戳，点击偏差 ≤ 2 秒
5. 失败兜底：链接失效给明确提示 + 本地上传入口（禁止静默失败）
出口标准：30 分钟视频解析成功率 ≥ 85%
注：本链路外部依赖重，W1 就应并行启动 POC，不要拖到最后
```

### P4 · W12–W13 内测打磨
```
进入 P4 阶段：性能优化、空态与异常态、新手引导、种子用户内测。

1. 空态/异常态全覆盖：无资料、解析中、失败、无网络、超限
2. 降级展示：转写成功但摘要失败时，保住已完成的字幕稿并告知
3. 新手引导：首次使用走通「上传→卡片→复习」
4. 10 名种子用户内测，回收 ≥ 30 条反馈
出口标准：10 名种子用户完成首周留存，P0/P1 缺陷清零
```

### P5 · W14–W15 上线准备
```
进入 P5 阶段：监控告警、成本护栏、支付与协议、备案材料。

1. 可观测：结构化日志（请求/用户/任务 ID）+ 指标（响应/积压/成功率/token）
2. 三条告警真实触发验证：解析失败率突增 / P95>5s / 日成本>120%
3. 四项观测进面板：模型连续失败 / 磁盘>80% / 接口错误率>2% / 契约失败率>5%
4. 成本护栏：日配额 + 单任务上限 + 全平台阈值自动降档
5. ICP 备案材料、用户协议、隐私政策
出口标准：G3 三项指标全部达标
```

### P6 · W16 灰度发布
```
进入 P6 阶段：5%→25%→100% 灰度、指标观察、回滚演练。

1. 灰度三档，每档观察 24 小时，盯错误率/AI 失败率/单用户成本三条曲线
2. 回滚演练：10 分钟内可回滚
3. Go/No-Go 逐域核验 G1–G7
出口标准：灰度期无重大故障，回滚 ≤ 10 分钟
```

## 二、分模块开发提示词

### 模块 1 · 用户与配额
```
实现用户体系与配额。
- 注册/登录/登出；密码 Argon2id；会话 HttpOnly Cookie 存 Redis，登出即失效
- 每日 token 配额与用量记录（cost_ledger）
- 配额扣减在 service 层，幂等（同一请求不重复扣）
- 越权防护：所有资源查询带 user_id 过滤
验收：越权测试用户 A 访问用户 B 资料返回 403；登出后 Cookie 失效
```

### 模块 2 · 可拖拽仪表盘
```
实现学习仪表盘（React 19 + AntD 5）。
- 卡片：今日任务、专注时长、学习进度、最近资源、趋势图、掌握度、学习日记
- 交互：拖拽排序、缩放（1×1/2×1/2×2）、隐藏/恢复、重置布局
- 布局持久化：变更自动保存到后端，刷新后还原
- 视觉：Apple 极简，石墨#1D1D1F + 前进蓝#0071E3，卡片圆角14px、银线#D2D2D7
验收：拖拽后刷新布局不变；1200px 与 768px 断点不重叠、不裁切
```

### 模块 3 · PDF 与卡片
```
实现 PDF 解析与背诵卡片。
- 上传走 MinIO 预签名直传，完成后核实大小与类型再建档
- 解析：文本层优先（PyMuPDF），扫描页 OCR 标置信度
- 切块参数严格按：章节切分 / 800字触发 / 300字块 / 100重叠
- 卡片：问答+填空，1块1知识点，带页码溯源
- 状态机四态；失败落错误码，不静默
验收：50 页 PDF P95 ≤ 60s；每章 ≥ 3 张卡；字段完整率 ≥ 95%
```

### 模块 4 · 题库与刷题
```
实现题库导入与智能刷题。
- 四格式导入：PDF / Word / Excel / TXT；清洗乱码、统一题号、识别题型
- 结构化：题干/选项/答案/解析四字段；不跳步解析固定五段（考点/思路/步骤/易错点/答案）
- 组卷：按知识点/难度/题型；在线答题；自动记错题
- 业务校验：选项不重复、答案落在选项内、分值合计 100
验收：100 题 Excel P95 全字段识别；五段缺一即判失败
```

### 模块 5 · 视频与笔记
```
实现多模态视频解析与笔记（见 P3 阶段，此处为模块视角）。
- 三级取材降本；三通道时间轴对齐
- 三类笔记：文稿/大纲/图文；时间戳可跳转（偏差 ≤ 2s）
- 关键帧拼图控制成本（V1.5 的关键帧截图嵌入）
验收：1 小时视频 P95 ≤ 25 分钟（本地转写）；链接失效有明确提示
```

### 模块 6 · AI 伴侣与计划
```
实现学习计划与成长记录。
- 目标 → 周计划 → 日任务；完成情况回流
- AI 依完成情况动态重排后续任务（中档模型，模板+参数填充兜底）
- 学习日记 + 润色（轻档模型，失败返回原文并提示未润色）
- 每周生成「薄弱知识点—建议动作」一句话清单
验收：计划生成 P95 ≤ 3s；重排后任务不冲突、不遗漏
```

### 模块 7 · 检索问答
```
实现检索增强问答（带来源）。
- 双路召回：向量前 20 + BM25 前 20，按块去重、双命中提权
- 重排：交叉编码器压在 3–5 条（重排为【已设计】，未实现时先按分数截断）
- 分数阈值 0.7 兜底；强制引用；拒答校验三层
- 权限过滤在召回阶段（不是生成后）
验收：每条答案可点开定位到原文；无依据时正确拒答
```

### 模块 8 · 部署与运维
```
实现部署与可观测（2C4G 单机三容器）。
- docker-compose：nginx + app(API+Worker 分进程) + data(PG+pgvector / MinIO 第二块盘)
- 磁盘水位 80% 冻结入队；终态任务自动清理；Redis 256MB 上限
- 日志结构化 + 指标聚合 + 三条告警 + 备份（DB 每日、MinIO 增量、不同盘）
- Alembic 迁移；TLS 90 天 certbot 续期
验收：G2 性能达标；恢复演练 RPO 24h/RTO 4h
```

## 三、功能落点对照（决定「现在该不该做」）

| 落点 | 范围 | 开发提示词使用 |
|---|---|---|
| **主线（27 项）** | 16 周内必须交付 | P0–P6 阶段提示词直接适用 |
| **V1.5（8 项）** | 答辩后 1–3 个月，可独立降级 | 用模板 A/B/C，但明确标注 V1.5，不占主线 |
| **规划池（3 项）** | 不承诺，仅主线有余量时 | **默认不开发**；除非用户明确要求 |

遇到需求先问：它属于哪个落点？V1.5 与规划池不要混进 16 周主线。

## 四、每次交付前的自查清单

- [ ] 是否违反架构铁律（CPU 密集/大文件/Redis/跨层/静默失败）？

## 五、答辩 / 演示准备提示词

### 模板 F · 生成三组可现场演示的验证
```
为答辩准备三组可现场演示的验证，用数据替代主观描述：
1. 解析准确率：用评测集对比 AI 抽取结果与人工标注，输出准确率/召回率/F1（文字版 ≥0.85、扫描件 ≥0.75）
2. 调度策略：固定间隔 vs 掌握度驱动，同等复习次数下记忆保持率对照（样本 ≥50 人、每人 ≥200 次复习、周期 ≥4 周）
3. 单任务成本：实测 PDF 卡片 / 视频笔记 / 题库解析单次成本，对照预算区间
要求：数据来自真实运行，不得编造；每组给出样本量、统计口径、结论一句话。
```

### 模板 G · 演示路径脚本（四条主路径走一遍）
```
按四条主路径准备可现场操作的演示脚本，每步都要有可见结果、不依赖网络偶然性：
① 上传→解析→卡片→复习：上传 30 页 PDF → 生成卡片 → 进今日任务
② 视频→笔记→卡片：粘贴 B 站链接 → 三种笔记 → 时间戳跳转 → 生成卡片
③ 组卷→错题→回炉：导入 100 题 Excel → 组卷 → 答题 → 错题本 → 回炉
④ 问答→溯源跳转：提问 → 带来源回答 → 点来源跳原文
每条路径准备一个"降级演示"（如断网/链接失效），证明失败提示友好、已完成部分不丢。
禁止：演示时临时改数据、用预制截图冒充实时结果。
```
