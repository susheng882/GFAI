## 0. 合规边界（先读，硬约束）

## 1. 调研口径

聚焦同一条闭环链路：**资料 → 笔记 → 卡片 → 刷题 → 复习**。每个产品只抽这段链路里的「布局骨架 / 关键交互 / 数据展示」，产品其他能力（社交、商业化、同步）不进表。

查证方式：WebSearch + WebFetch 实际抓官方文档/帮助中心/官方版本说明；版本与时间信息来自检索到的页面本身，不凭记忆补。

### 2.3 墨墨背单词（官网帮助 `maimemo.com/help30`；版本信息来自 v5.6.10 发布页 2026-11-09、v5.5.85 页面更新 2026-11-15）

|---|---|---|

### 2.8 跨产品共识 → GFLC 可迁移的 5 条

1. **单卡聚焦 + 翻面后再评分**（Anki / Quizlet / 墨墨 / RemNote 共同）：一次只给一张，答案与评分都在翻面后出现，避免一屏多卡分心。
2. **评分即排期**（Anki 四档显示下次间隔 / 墨墨四档改排期）：评分按钮要带「下次何时再见」的预期，而不是纯打分。
3. **今日队列是合并的一条**（墨墨「学习量」+ RemNote 侧栏到期数字 + Anki 三色计数）：due + 新学 + 计划任务合成「今日待办」，总量守恒。
4. **三栏可折叠且状态持久化**（Obsidian workspace 明确存 width + visibility）：折叠不是临时 UI 态，是可保存布局。
5. **同一数据多视图、笔记与卡片同源**（Notion 视图切换 + RemNote 行内卡）：降低「资料/笔记/卡片/题库」之间的数据割裂感。

## 3. 映射到 GFLC 现有页面（照着实现）

> 路径说明：任务书写的是 `web/src/pages/*`，仓库实际路径为 **`gflc/web/src/pages/*`**（已核对）。下列行号基于检索时文件状态，实现时以文件实际内容为准。

### 3.1 `gflc/web/src/pages/DocumentsPage.jsx` — 资料

- **抄什么结构**：BiliNote 左侧「上传入口 + 历史列表」的收拢感 + Notion「一个数据库多视图」的表格形态 + Anki 卡浏览器的「表头可筛/可排」。
- **放哪些区块**（自上而下）：① 拖拽上传条（**唯一实心主按钮**「上传资料」）② 资料表格 ③ 关联笔记摘要列表（次级，仅 `notes.length>0` 时出现）。
- **区块层级**：上传条 = 入口层 → 表格 = 主数据块（hero 级信息密度）→ 关联笔记 = 次级列表，字号与权重都下调一档。
- **表格列建议**：标题（500 + 来源类型/时间元信息）｜状态（ready/failed/pending）｜切片数｜**下一步**（见闭环状态条，指向笔记/卡片）｜操作（定位/解析/生成卡片/改名/删除）。列头支持筛选；状态用语义色而非品牌色。
- **空态**：当前 `locale.emptyText='还没有资料，上传一份 PDF 开始。'` 只是一行字 → 换成 `<EmptyState title="还没有资料" desc="上传一份 PDF、Word 或 Markdown，会自动解析并生成卡片。" action="上传资料" />`，动作点击触发 `fileRef.current.click()`。关联笔记区空态不渲染（现状已如此，保持）。
- **现状锚点**：`DocumentsPage.jsx:78-102`（列）、`:104-118`（上传条与表格）。

### 3.2 `gflc/web/src/pages/NotesPage.jsx` — 笔记

### 5.3 文案转化原则

- 标题写「这是什么」，不写「怎么操作」。例：不写「点击卡片翻面」，写「卡片正面」。
- 不给短句加句号、不用感叹号、不写「真实数据：」这类前缀。
- 产品术语中文化：deck→卡包，card→卡片，due→到期，review→复习，mastery→掌握度，queue→今日队列。
