# 35 · 视频解析类竞品对标（视频 → 笔记）

> 调研日期：2026-11-23 ｜ 范围：国内「音视频 → 结构化笔记」主线产品 ｜ 用途：给 GFLC 视频笔记模块补竞品参照
>
> 已有结论引用：BiliNote 的三段式、`[mm:ss]` 跳转、9 种笔记风格、关键帧缩略条、导图/复制/导出 Markdown，见 `22_市面学习闭环布局对标规范.md` §2.7，本文不重复查证。
>
> 本文只写「产物形态 / 时间戳与定位 / 转写与长视频 / 批量 / 导出 / 页面骨架」六件事，产品其他能力（商业化、社交、企业权限）不进表。

## 0. 结论先行

1. **「三栏」不是行业共识。** 通义听悟、飞书妙记、BibiGPT、Lumi、豆包插件全部是「播放器 + 右侧文本/结构化面板」两栏或覆盖式侧栏；只有 BiliNote 与 GFLC 把「历史视频列表」做成常驻左栏。三栏的代价是宽度：GFLC 在 1280px 以下已经自动退化成两栏（`app.css:230`），说明第三栏在笔记本屏幕上并不稳。
2. **主流产品把「逐字稿」放在播放器同栏（左侧上下叠放），右侧只放提炼结果。** GFLC 把文稿塞进右栏第 6 个 Tab，右栏同时承担「读笔记 + 查原文」两种任务，Tab 数量偏多。
3. **GFLC 的产物形态不落后，落后的是「结构 → 定位」和「产出 → 导出/复习」两段。** 四模板 + Markdown + 关键帧 + 树状导图在形态上比通义/飞书更贴近学习；但大纲节点没有时间戳、笔记只读、页面没有导出与转卡片入口，导致「看完了」不能顺畅走到「存下来 / 背起来」。
4. **批量能力 GFLC 已进入第一梯队**（50 条队列、串行提交、逐条进度、失败重试），通义听悟官方也是 50 个文件批量；但「批量导入」不等于「合集汇总」——BibiGPT 有合集级总览 + 导图，GFLC 没有，且 B 站合集/分P 不会自动展开（后端 `noplaylist: True`，`services/video.py:534`）。
5. **真正值得抄的近身能力只有 6 条**：导图/大纲节点带时间戳、笔记可编辑、文稿搜索与播放跟随、Markdown/SRT 导出、视频页「转卡片」闭环、沉浸式纯笔记模式。协作评论、发言人分离、片段分享对「个人考试学习」场景价值低，不建议追。

## 2. 视频笔记页布局骨架对比

### 2.1 三栏/两栏骨架与占比

| 产品 | 左栏 | 中栏 | 右栏 | 占比与伸缩 | 层级特征 |
|---|---|---|---|---|---|

| 飞书妙记 | 视频（上）+ 发言人 / 会议信息（下） | — | 「智能纪要 / 文字记录」双 Tab | 中间分隔栏**可拖动**（官方原文），用户自定 | 两栏：右栏一级 Tab 区分「纪要 / 逐字稿」 |

| Lumi | 宿主页原播放器（全宽） | — | 右侧学习面板（总结/字幕/阅读稿/对话/笔记） | 覆盖式，面板不挤压播放器 | 0 栏 + overlay；不重排宿主页 |

| **GFLC** | 上传 + 批量 + 历史视频（268px） | 播放器 + 关键点 + 关键帧（`1fr`，最小 300px） | 6 Tab 笔记（`1.25fr`，最小 380px） | 1440px 下约 **18% / 36% / 45%**；<1280 变两栏、<860 单栏（`app.css:229-244`） | **三栏**：左「任务+资产」，中「看」，右「读」 |

### 2.2 区块层级（L0 / L1 / L2）

| 产品 | L0 全局层 | L1 工作区 | L2 栏内区块（自上而下） |
|---|---|---|---|
| 通义听悟 | 记录标题 + 导出 / 分享 | 左播放器+转写 ｜ 右 AI 面板 | 左：播放器 → 转写（发言人分段）；右：全文摘要 → 章节速览 → 发言总结 → 问答回顾 → PPT |
| 飞书妙记 | 标题 + 分享 / 导出 / 语言 | 左视频+发言人 ｜ 右纪要 | 左：视频 → 发言人时间轴 → 会议信息；右：一级 Tab（智能纪要 / 文字记录）→ 内容 |
| BibiGPT | 链接输入 + 模型选择 | 播放器 ｜ 结果 | 结果：一级 Tab（总结 / 亮点 / 章节细读 / 导图 / 闪卡 / 对话）→ 内容 |
| Lumi | 宿主页播放器 | 播放器 ｜ 右侧面板 | 面板：总结 → 字幕 → 阅读稿 → 对话 → 笔记（Tab 切换） |
| 豆包插件 | 宿主页 | 播放器 ｜ 侧栏 | 总结 / 大纲 / 脑图 / 问答 |
| **GFLC** | 步骤条（视频源→转写→笔记→配图）+ 折叠按钮 | 左列表 ｜ 中播放器 ｜ 右笔记 | 左：上传卡 → 批量统计 → 历史列表；中：播放器 → 关键点 → 关键帧；右：6 Tab → 正文 |

### 2.3 从骨架看出的三个问题

1. **GFLC 右栏职责过载。** 6 个 Tab 里，「笔记 / 摘要 / 大纲 / 问答 / 图文」是**产物**，「文稿」是**原料**。竞品把原料放在播放器同栏（通义、飞书），GFLC 把它放在产物栏，导致用户在「读笔记」和「查原话」之间要切 Tab。建议右栏一级分「笔记 / 文稿」两个视图，二级再放摘要/大纲/问答/图文；或把文稿移到中栏播放器下方（通义式）。
2. **左栏 268px 的历史列表在 1280px 以下不成立。** 现有断点已经把它降级为两栏，右栏被推到下一行，用户实际看到的是「左+中」一屏、「右」一屏。若坚持三栏，建议左栏改为**可收起的抽屉**（默认收起，点「历史」滑出），把宽度让给播放器与笔记。
3. **中栏的信息层级比竞品多一层。** GFLC 中栏是「播放器 → 关键点 → 关键帧」三块纵向堆叠，竞品中栏基本只有播放器。好处是定位信息集中，坏处是播放器被压矮。建议关键点与关键帧合并为一个「时间轴」卡片，内部用 Segmented 切「章节 / 帧」，减少一块卡片高度。

## 3. GFLC 缺失清单（含成本与接口）

> 接口现状核对：任务书列的 `/videos/{id}` **在代码中不存在**；实际是 `GET /videos`（列表）、`GET /videos/{id}/notes`（详情+笔记+文稿+帧）、`GET /videos/{id}/stream`、`DELETE /videos/{id}`。另已存在 `GET /notes/{id}/export`、`PATCH /notes/{id}`、`POST /notes/{id}/to-cards`、`GET /tasks/{id}`。
>
> 成本口径：**低** = 单前端文件或复用现成接口；**中** = 前端 + 提示词/Schema，或新增 1 个后端端点；**高** = 新数据模型或新服务。

|---|---|---|---|---|---|
| 1 | 视频页无 Markdown 导出入口 | BibiGPT / Lumi / 学知云课记 | 低 | 不需要（复用 `GET /notes/{id}/export`） | **P0** |

## 4. 特别评估：GFLC 与竞品的真实差距

### 4.1 已实现能力对照

| 能力 | GFLC 现状 | 竞品水平 | 判断 |
|---|---|---|---|
| 四模板笔记 | 摘要 / 大纲 / 问答 / 图文 四类，另加单篇 Markdown 主笔记（`VideoPage.jsx:11-14`、`handlers.py:225-300`） | 通义：摘要/章节/发言/问答/PPT；飞书：纪要+逐字稿；BibiGPT：总结/亮点/章节细读/导图/闪卡/对话 | **形态不落后，学习属性更强**（问答 + 图文是复习导向，通义/飞书偏会议） |
| 时间戳跳转 | 笔记 `[mm:ss]` → `?t=`、图片 alt=`mm:ss`、关键点、转写片段均可 seek，`seek()` 统一收敛（`VideoPage.jsx:107-118, 345-358`） | BibiGPT / Lumi / 豆包 / BiliNote 均有；通义/飞书靠转写点击 | **第一梯队，但不是独有**；差距在「大纲节点不能跳」 |
| 关键帧截图 | 提示词强制 6–20 个 `*Screenshot-[mm:ss]`，ffmpeg 精确抽帧，图与秒数绑定（`video_note.py:28-35, 91-127`） | BiliNote 有关键帧条；通义抽 PPT 页；豆包提关键帧；BibiGPT 偏视觉分析 | **同级偏好**：GFLC 的「按知识点强制配图」比通用抽帧更贴刷题/板书 |
| 树状大纲 | markmap 渲染 `##/###` 为节点树，可缩放/适应（`MindMap.jsx`） | BibiGPT 导图可点节点跳；通义 4 层导图；豆包脑图可定位 | **落后一处**：节点无时间戳，导图只是「图」，不是「导航」 |
| 整季批量 | 50 条队列、串行提交、逐条状态/进度、失败重试（`VideoPage.jsx:159-319`） | 通义 50 文件批量；飞书多文件；BibiGPT 合集 | **第一梯队**；但「批量」≠「合集」，且不自动展开 B站合集 |
| 与复习闭环 | 有卡片系统、`to-cards`、复习页 | BibiGPT 闪卡导出 Anki；GFLC 原生闭环更短 | **潜在优势，当前断在视频页没有入口** |

### 4.2 真实差距只有四条

1. **结构不能定位。** 大纲/导图好看，但点节点不回原片；竞品（BibiGPT、豆包）已经把「图」变成「导航」。这是最值得补、也最容易补的一条。
2. **笔记是「只读产物」，不是「可加工的稿」。** 通义、飞书都能改错字、补一句；GFLC 的 ASR 错字只能重跑。学习者对 AI 笔记的第一动作往往是「删掉废话、补自己的话」，只读会逼用户复制到别处。
3. **产出不能带走。** 后端有 Markdown 导出能力，页面没有按钮；没有 SRT/TXT，也没有「笔记 + 截图 + 文稿」打包。竞品全部把导出放在显眼位置。
4. **长文稿不可检索。** 60 分钟视频的文稿是几千字，只有滚动没有搜索；飞书/Lumi 都把搜索框放在文稿顶部。这是纯前端就能解决的体验断层。

### 4.3 不建议为了「凑缺口」而做的

- **发言人分离 / 发言人总结**：课程视频多为单讲师，收益低、管线重。
- **评论、@、片段分享、权限**：这是会议协作产品的核心，不是个人备考工具的主线；做了会稀释「资料→笔记→卡片→刷题→复习」。
- **视频内 AI 追问**：价值真实，但需要「按章节取上下文 + 引用时间戳 + 成本控制」一整套，属于下一个版本的能力，不应挤占 P0。
- **复刻 BibiGPT 的 30+ 平台**：平台面是流量策略，GFLC 的差异在「解析后能复习」，不在「什么链接都能贴」。

## 5. 合规边界

1. **只借鉴交互逻辑与信息结构，不复制像素。** 不抄通义听悟的卡片圆角/阴影、飞书妙记的蓝、BibiGPT 的渐变、Lumi 的面板样式；所有视觉落点走 GFLC token（颜色、字号、圆角、发丝线）。
2. **不复制图标与品牌文案。** 不使用「听悟」「妙记」「闪记卡」「章节细读」「沉浸模式」等作为 GFLC 的功能名；GFLC 用自己的说法：`关键点`、`文稿`、`转卡片`、`专注`（若做）。
3. **不复制提示词与模板文本。** 通义/飞书/BibiGPT 的总结模板、章节标题规则、问答生成提示词均不直接搬运；GFLC 现有 `video_note.py` 提示词为自写，BiliNote 仅借鉴公开范式且已在文件头标注 MIT 来源，继续保持。
4. **不声称「同款能力」。** 对外文档/界面不写「对标通义」「BibiGPT 同款」；不引用其准确率、转写速度等营销数字（如「98%」「1 小时 3 分钟」）作为 GFLC 指标。
5. **数据与隐私。** 竞品的云同步、分享、协作能力不引入；GFLC 继续本地/自托管路线，导出文件由用户自己保管。
6. **本次调研只读**：未登录任何竞品账号、未抓取需登录页面、未复制其界面资源；所有结论来自公开官网/帮助中心/公开测评，无法核实处标「未查证」。

### 6.2 核心结论 5 条

1. 行业主流是「播放器 + 右侧结构化面板」两栏/覆盖式侧栏，三栏是 BiliNote 与 GFLC 的选择，不是共识；GFLC 在 1280px 以下已实际退化为两栏，左栏历史列表应考虑抽屉化。
2. GFLC 的产物形态（四模板 + Markdown + 关键帧 + 树状导图）不落后，学习属性强于会议型产品；真正落后的是「大纲节点不能跳时间」「笔记只读」「文稿不能搜」「产出不能导出」。
3. 最划算的 6 个补丁全部不需要新后端接口：Markdown 导出、大纲/问答时间戳可点、文稿搜索、笔记编辑、转卡片、播放跟随（其中转卡片与导出均已有现成接口）。
4. 「整季批量」已进第一梯队（50 条 + 串行 + 进度 + 重试），但「批量导入」不等于「合集汇总」；B站合集/分P 自动展开与合集级总览是下一阶段的高成本项，不应与 P0 混做。
5. 不建议追发言人分离、协作评论、片段分享与视频内 AI 追问；这些会把个人备考工具推向会议协作产品，稀释闭环。
