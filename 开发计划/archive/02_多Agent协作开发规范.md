# GFLC 多 Agent 协作开发规范

> 目标：让多个 Agent（人或 AI）并行开发同一个项目而**不互相踩踏**，且每层都有明确验收标准。
> 适用：本项目 `gflc/`（FastAPI + 原生前端 + DeepSeek + faster-whisper）。

---

## 一、角色分工（5 个 Agent）

| Agent | 职责 | 可改目录（所有权） | 交付物 | 不做什么 |
|---|---|---|---|---|
| **A1 后端** | API、数据模型、鉴权、存储、队列 | `backend/app/{routers,services,crud,models,db,core,worker}` `backend/migrations` | 可运行接口 + 单测 | 不改前端、不改 AI Prompt |
| **A2 前端** | 页面、交互、设计系统、主题 | `backend/frontend/`（或未来 `frontend/`） | 可交互页面 | 不改后端逻辑、不硬编码接口 |
| **A3 AI 管线** | Prompt、契约、解析、检索、转写、成本 | `backend/app/ai/` `backend/app/services/{parse,chunking,rag,video,question_parse}.py` | Prompt 版本 + 契约 + 评测指标 | 不改路由、不改 DB 结构 |
| **A4 测试/QA** | 单测、契约测试、E2E、门禁核验 | `backend/tests/` `docs/qa/` | 测试报告 + 缺陷清单 | 不改业务代码（只提 issue） |
| **A5 文档/交付** | README、ADR、验收报告、部署说明 | `docs/` `开发计划/` `README.md` | 文档 + 交付清单 | 不改代码 |
| **A6 设计/UI** | 设计系统、视觉规范、仪表盘与图表、交互一致性 | 前端样式与组件层、`docs/design/` | 设计 token + 组件 + 视觉验收 | 不改业务逻辑与接口 |

**铁律**：任何 Agent 只写自己所有权的目录；跨域改动必须先在「协作任务板」登记，由对应 owner 执行。

---

## 二、协作铁律（防冲突）

1. **契约先行**：`OpenAPI(/openapi.json)` + Pydantic Schema 是唯一事实源。前端只依赖契约，不猜字段。
2. **接口冻结**：进入联调后，改接口必须 A1 在任务板公告，A2/A4 确认后才合并。
3. **单一写者**：一个文件同一时间只有一个 owner 在改；并行时按目录切分，不按文件切分。
4. **小步提交**：一次提交只做一件事，commit message 用 `feat|fix|refactor|test|docs(scope): 说明`。
5. **可回滚**：每个功能完成后打一个可运行版本（tag 或 commit），保证任何时候能回到「跑得起来」的状态。
6. **不越权验收**：写代码的人不能给自己的功能签字，必须由 A4 独立验收。

## 三、开发约束

### 3.1 代码
- 后端严格分层：`routers`（参数/鉴权/组装）→ `services`（业务）→ `crud`（读写），**禁止跨层**。
- 所有外部依赖（LLM/存储/转写）走适配器，业务代码不直接 import SDK。
- 统一错误码（`AUTH-401`/`PARSE-002`/`AI-003`…），失败必返回 `{ok:false,error:{code,message}}`，**禁止静默失败**。
- 类型：Pydantic 校验入参出参；AI 输出必须过 Schema。

### 3.2 安全
- 密钥只放 `.env`（已 gitignore），**代码零硬编码**。
- 越权：所有查询带 `user_id` 过滤；用户 A 不得读到 B 的资料。
- XSS：前端所有插值走 `esc()`；后端不返回未净化 HTML。
- SQL 注入：全部参数化（SQLAlchemy），禁止字符串拼 SQL。
- 上传：后缀白名单 + 大小上限 + 服务端二次校验。

### 3.3 性能与成本
- 同步接口只放短查询；重活（转写/解析/批量）走异步或独立进程。
- 列表必须分页（`limit`），禁止全表捞出后在内存过滤。
- LLM 调用：三档路由 + 结果缓存 + 单任务 token 上限；单次成本对照预算（PDF 0.08–0.12、视频 0.25–0.40）。
- 视频转写：默认 `WHISPER_MODEL=base`（中文可读），长视频建议分段/云端兜底。

### 3.4 数据
- 迁移只走 Alembic；禁止手写改表。
- 写操作幂等（内容哈希去重）；事务边界清晰。
- 状态机四态：`pending → parsing → ready / failed`，失败落错误码。

## 四、测试与验收标准（每层签字线）

### 4.1 后端（A1 → A4 验收）
| 项 | 标准 |
|---|---|
| 单元测试 | 核心模块行覆盖 ≥ 70%，`pytest` 全绿 |
| 契约测试 | 每个 AI 任务输出 Schema 校验通过率 100% |
| 接口测试 | 每个端点：正常 / 参数非法 / 未登录 / 越权 四类用例 |
| 性能 | 关键接口 P95 ≤ 3s（不含 LLM）；列表接口 ≤ 500ms |
| 幂等 | 同文件重复上传返回 `dedup=true`，不重复计费 |

### 4.2 前端（A2 → A4 验收）
| 项 | 标准 |
|---|---|
| 功能 | 8 个页面（仪表盘/文档/题库/刷题/计划/复习/问答/视频）可操作 |
| 响应式 | 1280 / 768 / 375 三档不重叠、不裁切 |
| 主题 | 亮/暗模式切换正常，token 一致 |
| 交互 | 加载态（spin）、空态、错误 toast 齐全；按钮防重复点击 |
| 视觉 | 遵循 shadcn token（语义色/1px 边框/圆角派生），无"AI 拼图感" |
| 可访问性 | 键盘可聚焦、对比度达标、`prefers-reduced-motion` 降级 |

### 4.3 AI 管线（A3 → A4 验收）
| 项 | 标准 |
|---|---|
| 卡片 | 字段完整率 ≥ 95%，卡片可用率 ≥ 85% |
| 题目 | 五段解析缺一即失败；选项/答案结构正确 |
| 检索 | 命中率（前 3 含答案）逐版不降；无依据时必须拒答 |
| 引用 | 回答带 `[n]` 且 sources 有页码 |
| 转写 | 讲解类视频可读；无语音时明确报错，不静默 |

### 4.4 E2E（四条主路径，A4 执行）
1. 上传 → 解析 → 卡片 → 复习
2. 视频链接/上传 → 转写 → 笔记 → 卡片
3. 题库导入 → 组卷 → 答题 → 错题本
4. 问答 → 带引用 → 来源页码

### 4.5 上线门禁（G1–G7 摘要）
- G1 功能与质量（一票否决）：主路径 100%、解析成功率 ≥ 90%
- G2 性能：P95、并发、超限拒绝
- G3 安全：HTTPS、Argon2id、越权测试、日志脱敏
- G4 可恢复：每日备份、恢复演练
- G5 可观测：三条告警 + 四项观测
- G6 发布：CI 绿、回滚 ≤ 10 分钟
- G7 合规：ICP、协议、内容声明

## 五、一轮迭代的标准流程

```
① A5/A1 写任务卡（目标/接口/验收）
   ↓
② A1 冻结 OpenAPI 契约（前端可先 mock）
   ↓
③ 并行开发：A1 后端 ∥ A2 前端(mock) ∥ A3 AI
   ↓
④ 集成：后端真实接口 → 前端切换
   ↓
⑤ A4 独立验收（按第四节逐条）→ 出缺陷清单
   ↓
⑥ 修复 → 回归 → A5 交付报告 + tag
```

**任何一步失败，不进入下一步。** 宁可少一个功能上线，不可交付跑不起来的版本。

## 七、设计与技术专项约束（A6 主导，全员遵守）

### 7.1 设计系统（单一事实源）
- **token 体系**：颜色只走语义变量（`--background/--card/--primary/--muted/--border/--destructive` 等），**禁止在组件里写死 hex**。
- **圆角**：从 `--radius` 派生（`calc(var(--radius)*0.8/1.4/1.9)`），不散落魔法数字。
- **分层**：平面靠 1px `--border`，浮层才用阴影；hover 用 `--secondary` 浅底，不做发光/形变。
- **图表色**：主色 `--primary`，辅助用 `--chart-1..5`；同图不超过 3 色。
- **亮暗双模式**：新增颜色必须同时给 `.dark` 值，否则不合并。

### 7.2 组件规范
- 按钮 6 变体（primary/secondary/outline/ghost/danger/link）+ sm/md 尺寸，统一 `h-34px`。
- 卡片三段式（标题/内容/操作），`padding 16–20px`，标题 14px，正文 13.5px，次级文字 `--muted-foreground`。
- 表格：表头 12px muted、行 hover `--muted`、不画竖线、末行去 border。
- 空态/加载态/错误态三态齐全；加载用 `spin`，禁止空白页。

### 7.3 AI 仪表盘卡片契约（重要）
AI 生成的仪表盘**只允许**以下卡片类型，前端按 type 渲染，后端 Schema 强校验：

| type | 适用 | 必备字段 | 建议跨度 |
|---|---|---|---|
| `stat` | 单个关键指标 | value, unit, hint | 3 列 |
| `bar` | 分类对比 | data[{label,value}] | 6 列 |
| `line` | 趋势 | data[{label,value}] | 6 列 |
| `ring` | 完成率/占比 | value, max(默认100) | 3 列 |
| `progress` | 进度条 | value, max | 4 列 |
| `list` | 要点清单 | items[] | 4 列 |

约束：一次 6–8 张卡；数值必须自洽（如剩余天数 × 每日时长 ≈ 总学时）；不得编造真实机构数据；卡片 `id` 唯一且稳定（拖拽顺序依赖它）。

### 7.4 技术约束（接口与性能）
- 生成类接口（AI 仪表盘/计划/题库）统一返回 `{id, ...}`，前端据此可回查。
- 布局持久化：拖拽后 **PUT 顺序**，刷新必须还原（已验证）。
- 所有 id 全局唯一：**同一页面禁止重复 `id`**（曾因 `#theme` 冲突导致功能失效）。
- LLM 调用必须设 timeout + 失败降级；单次生成 ≤ 30s，超时给明确提示。
- 静态资源由后端托管时，前端改动无需重启（实时生效），但**后端改动必须重启**。
