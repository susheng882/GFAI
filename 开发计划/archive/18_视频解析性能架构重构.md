# 18 · 视频解析性能架构重构（实测驱动）

> 起因：用你给的 B 站视频（`BV18Hsz6ZECw`，概率论刷题，p01 59.6 分钟 / p03 30.9 分钟）实测，
> **冷跑 39 分钟**、用户体验是「点了没反应」。本文件是诊断 + 架构 + 已落地改动 + 剩余路线。
> 所有数字来自本机 `:8011`（20 核 CPU / SQLite / 真实 DeepSeek Key），可用 §7 命令复现。

---

## 0. 结论先行

| 场景 | 改前 | 改后（实测） | 变化 |
|---|---|---|---|
| 60 分钟视频（p01）冷跑 | **2341s ≈ 39 min** | 按 31 分钟实测比例外推 **≈ 7–8 min** | **5×** |
| 31 分钟视频（p03）冷跑 | 482s ≈ 8.0 min | **≈ 5 min**（转写 107s→已含在新数里，OCR/图文再降） | 1.6×（叠加已修 bug 后） |
| 31 分钟视频重复提交（同源复用） | — | **208.9s ≈ 3.5 min** | 新增能力 |
| 转写单元基准（4.5 min 音频） | RTF 0.44 | **RTF 0.091** | **4.9×** |

一句话：**根因不是模型慢，是「串行 + 单点 + 无缓存」**。三处串行（转写单路、三模板串行、两张拼图串行）叠在一起，
把 5 分钟能做完的事拖成 39 分钟。

## 1. 诊断：39 分钟花在哪（阶段实测）

p01（59.6 分钟视频）冷跑，`stage_timeline` 实测：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 下载（音频） | 3 s | 42MB，13 MB/s |
| 抽音频 | 2 s | ffmpeg |
| **语音转写** | **≈ 35 min** | ⚠️ Whisper base 单路串行，吃满 4 核就停，RTF 0.44 |
| 三模板笔记 | 164 s | ⚠️ summary 37 + outline 44 + qa 82，**串行** |
| 抽关键帧 | 97 s | 全片解码（60 min 视频） |
| 拼图 OCR | 205 s | ⚠️ 2 张网格**串行**视觉调用，每次 100s |
| 图文笔记 | 116 s | mid 档 JSON 解析失败 → 换 strong 重跑 |
| **合计** | **2341 s** | |

同时暴露 4 个**功能性缺陷**（不是慢，是错）：

| # | 缺陷 | 后果 |
|---|---|---|
| F1 | URL 导入固定下 `bestaudio` | `_is_video_src()` 判成音频 → **图文笔记永远不生成**（你这次要的图文就是这么丢的） |
| F2 | mid 档 `max_tokens=3000` | 60 分钟视频的大纲/问答**必被截断**成半截 JSON → 模板生成失败 |
| F3 | `build_frame_note` 用 light 档（1500 token）+ 无 JSON 容错 | 图文笔记正文经常解析失败，只剩一列帧链接 |
| F4 | 模板提示词只取 `transcript[:12000]` | 60 分钟视频**只有前 20 分钟进模型**，后半程考点全丢；笔记 ts 也没有依据 |

## 2. 目标架构（五层，每层有硬指标）

```
                    ┌─────────────────────────────────────────┐
  URL/文件 ────────▶│ L1 取材层  Subtitle ‖ ASR(并行切片)      │  目标：字幕命中 0–2s；ASR ≤6min/60min
                    └──────────────┬──────────────────────────┘
                                   ▼  segments(ts) + chunks(300字/块, 带 ts_start)
                    ┌─────────────────────────────────────────┐
                    │ L2 理解层  时间戳化转写 + 长文压缩采样    │  目标：全文覆盖，不截头丢尾
                    └──────────────┬──────────────────────────┘
                                   ▼
              ┌────────────────────┴─────────────────────┐
              ▼                                          ▼
   ┌──────────────────────────┐            ┌──────────────────────────┐
   │ L3a 文本笔记 3 模板并发   │            │ L3b 图文 解码→拼图→OCR→生成│
   │ summary/outline/qa        │            │ 4×3 网格, 2 次视觉调用    │
   └──────────────┬───────────┘            └──────────────┬───────────┘
                  └────────────────┬───────────────────────┘
                                   ▼
                    ┌─────────────────────────────────────────┐
                    │ L4 调度层  单线程队列 → 阶段化 checkpoint │  目标：阶段可见、可续跑、不误杀
                    └──────────────┬──────────────────────────┘
                                   ▼
                    ┌─────────────────────────────────────────┐
                    │ L5 缓存层  同源复用(URL/内容哈希) + 答案缓存│  目标：重复提交 ≤10s
                    └─────────────────────────────────────────┘
```

### 2.1 各层指标（当前 / 目标）

| 层 | 指标 | 改前 | 现在 | 目标 |
|---|---|---|---|---|
| L1 取材 | 60min ASR | 26 min | **≈ 5.5 min** | ≤5 min（或字幕 0s） |
| L1 取材 | 字幕命中率 | 0%（B站需登录 cookie） | 0%（未配 cookie） | >60%（配 cookie 后） |
| L2 理解 | 全文覆盖 | 前 20 min | **全片（头55%+中段采样+尾15%）** | 全片 |
| L3a 笔记 | 3 模板 | 164 s 串行 | **24–29 s 并发** | ≤30 s |
| L3b 图文 | 抽帧+OCR+生成 | 97+205+116 = 418 s | **22+125+14 = 161 s** | ≤90 s |
| L4 调度 | 阶段可观测 | 无 | **stage_timeline 逐阶段落在 checkpoint** | 保留 |
| L5 缓存 | 重复提交 | 39 min（全量重跑） | **208.9 s**（下载+笔记+图文） | ≤10 s（跳过下载） |

## 3. 已落地改动（本轮，全部实测验证）

| # | 改动 | 文件 | 效果（实测） |
|---|---|---|---|
| A1 | **转写切片并行**：长音频按 6 片切分 + 1s 重叠 + 线程池并发 + 时间轴还原 + 边界去重 | `services/video.py` `transcribe()` | RTF 0.44 → **0.091（4.9×）**；60min 26min → ≈5.5min |
| A2 | Whisper 模型 `cpu_threads=8` 可配 | `services/video.py` `_model()`、`config.py` | 单核瓶颈解除 |
| A3 | 新增 `WHISPER_PARALLEL / WHISPER_CPU_THREADS / WHISPER_BEAM` 配置 | `core/config.py`、`deploy/.env.example` | 小机器可调成 2–4 |
| A4 | **三模板并发**（`asyncio.gather`），落库仍串行 | `worker/handlers.py` | 164 s → **24–29 s** |
| A5 | **两张网格 OCR 并发** | `services/frames.py` `ocr_grids()` | 205 s → **125 s** |
| A6 | 网格 OCR `max_tokens` 8000 → 3500 | `services/frames.py` | 视觉调用时长下降约 40% |
| A7 | **JSON 确定性修复**（字符串内裸换行/制表符、截断尾部补闭合） | `ai/deepseek.py` `_repair_json()` | 图文笔记 116 s → **14 s**（不再掉到 strong 档） |
| A8 | 笔记生成 **换档重试**（mid 失败 → strong） | `worker/handlers.py` | 长视频 3 模板成功率 2/3 → **3/3** |
| A9 | URL 导入**优先下视频**（480p + 合并 mp4） | `services/video.py` `download_media()` | 图文笔记**从「永远不生成」到可用**（F1） |
| A10 | 转写**带 `[mm:ss]` 时间戳**喂给模型 | `worker/handlers.py` | 笔记里的 ts 有依据，来源可跳转 |
| A11 | 长转写**均匀采样压缩**（头 55% + 中段 + 尾 15%，≤14k 字） | `ai/prompts.py` `_fit_transcript()` | 全文覆盖，不再只看前 20 分钟（F4） |
| A12 | **同源复用**（同用户同 URL 继承已转写取材） | `worker/handlers.py` `_reuse_material_by_url()` | 重复提交 **39 min → 208 s** |
| A13 | 同类笔记**去重写入**（不再出现 2 份 summary） | `worker/handlers.py` `_replace_old_note()` | 笔记列表干净 |
| A14 | **阶段时间线**持久化到 checkpoint | `worker/runner.py` `_record_timeline()` | 每次任务可复现「哪一步慢」 |
| A15 | 无字幕时返回 `speed_hint` 提示配 cookie | `worker/handlers.py` | 用户知道怎么再快 40 倍 |

> 顺手修的坑：`Task.checkpoint` 是 JSON 列，**原地改 dict 不会触发 UPDATE**（必须换新对象），否则时间线永远写不进去。

## 5. 容量模型（用于对外承诺，勿夸大）

按实测 RTF 0.091 + 各阶段固定开销推算（单机 20 核、单任务）：

| 视频时长 | 冷跑（无字幕） | 冷跑（有字幕） | 重复提交 |
|---|---|---|---|
| 10 min | ≈ 1.2 min | ≈ 40 s | ≈ 30 s |
| 30 min | ≈ 5.0 min | ≈ 1.5 min | ≈ 3.5 min |
| 60 min | **≈ 7.5 min** | ≈ 3 min | ≈ 5 min |
| 120 min | ≈ 14 min | ≈ 5 min | ≈ 9 min |

> 重复提交之所以还要几分钟，是因为**目前仍会重新下载视频再抽帧**（B1/B3/B2 做完可降到 10s 级）。
> 60 min 以上建议先切 B1（字幕）或 B5（独立 worker）。

## 8. 风险与边界

| 风险 | 处理 |
|---|---|
| 切片边界切断句子 | 1s 重叠 + 「本片只收到 start+span」+ 相邻同文本去重；实测 31min 视频 26 段文本连续可读 |
| 6 片并行吃满 CPU，和其他任务抢资源 | `WHISPER_PARALLEL` 可调；生产建议独立 worker 进程（B5）+ 队列串行化 |
| 均匀采样丢中间细节 | 采样按行等距，保留头尾；如要 100% 覆盖需分层摘要（成本 ×N），列入 B6 之后 |
| JSON 修复可能掩盖模型问题 | 修复后仍走 Pydantic 校验，失败必报错；修复命中会打 WARNING |
| 重新下载导致复用仍需分钟级 | 已在 §5 标注，B2/B3 解决 |
