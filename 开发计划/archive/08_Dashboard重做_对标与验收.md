## 〇、先明确一件事：不复制像素

「一比一复刻某产品」这一步不做，原因有两个，都是实际风险：

1. **法律**：Logo、插画、图标集、文案属于受保护内容，像素级照搬有版权与商标风险；
2. **产品**：像素复刻的结果永远落后一代，而且会做出"四不像"——拿来 Linear 的列表 + Stripe 的图表 + Vercel 的黑底，组合起来比原来更差。

**改成复制决策**：每个标杆拆出 1 条可量化的做法（栅格比例、字体阶梯、强调色面积、widget 数量上限），把这些数值用到自己的产品上。这样评审时能逐条对照，而不是"看着像不像"。

本文第 1 节的每一条，都能落到第 3 节的数值和第 4 节的验收项。

## 一、对标清单（8 个 + 2 份统计口径）

| # | 产品 | 它做对的那一件具体事 | 我们采用什么 | 我们不采用什么 |
|---|---|---|---|---|
| 1 | **Stripe Dashboard** | 每张图默认带时间范围（今天 / 7 天 / 30 天），点图下钻到明细 | 主图右上角放 `今天 / 7 天 / 30 天` 分段，切换只重绘一张图 | 不做下钻明细页（我们数据量不够，会点进空页） |
| 2 | **Linear** | 一屏只有一个 hero metric，其余全部降级；空状态当成 onboarding | hero = "今天要复习 27 张"，全屏唯一 40px+ 数字 | 不做 issue 列表那种 3 栏常驻 |
| 3 | **Notion** | 首屏放 "Continue working on"，让人接着上次的活 | 「继续上次」区块：笔记 / 题库各一条，带上次打开时间 | 不做可拖拽的卡片墙（那正是我们这次要拆掉的） |
| 4 | **Vercel** | 克制的 bento：卡片大小有节奏，但只有一张主图 | `8+4 / 4+4+4 / 6+6` 的行节奏，主图独占 8 列 | 不做纯黑高对比（我们是长时间阅读的产品） |
| 5 | **Mercury / Ramp** | 先用一个大数字建立信任，其余全是它的解释 | hero 数字后面紧跟一句解释：`+5 相比昨天 · 预计 18 分钟` | 不做金融化的深色大屏 |
| 6 | **Raycast / Sentry** | 深色是一等公民，一个强调色，对比度严格 | 深色单独校色（上一轮已做），全站只有一个强调色 | 不做纯黑 + 霓虹 |
| 7 | **Datadog** | 密集但可读：行高统一、数字等宽、表头安静 | 等宽数字 + 表格行高 44 + 表头 11.5/400 | 不做满屏 widget 拼贴 |
| 8 | **Superhuman / Zendesk** | split-pane 三栏处理高频流程 | 用在「复习」页（队列 + 卡片），不放在仪表盘 | 仪表盘不做三栏 |
| 9 | **Gummble 2026 统计口径** | 主视图 **5–7 个 widget**，1 hero + 4–6 支撑；超过 7 个触到认知上限 | 定为硬指标 A1 | — |
| 10 | **codefronts 2026** | bento 用 `repeat(auto-fit,minmax(240px,1fr))` + container query，让卡片按自身宽度重排，不用 JS | 响应式实现方式（A10 的验收依据） | 不引入框架，纯 CSS |

**结论：采用 8 条做法，砍掉 5 条**。砍掉的部分都是"看起来更像那个产品、但对我们没用"的。

## 四、验收标准（14 条，每条都有测法）

### 视觉与信息

| # | 标准 | 测法 |
|---|---|---|
| **A1** | 一屏数据块 ≤ 7 个 | 统计 `.body > .grid > section` 数量 |
| **A2** | 一屏主按钮（实心墨色）= 1 个 | 统计可见的 `.btn`（背景 = `--btn`）= 1 |
| **A3** | hero 字号 / 次一级字号 ≥ 1.8 | 44 / 22 = 2.0 |
| **A4** | 所有 padding/margin/gap 是 4 的倍数 | 脚本遍历 computedStyle，允许 2px 以内微调 |
| **A5** | 字号 ≤ 8 档、字重只有 400/500 | 脚本收集 `fontSize`/`fontWeight` 去重 |
| **A6** | 强调色同屏 ≤ 4 处，且每处都表意 | 人工核对 + 截图标注 |
| **A7** | 无渐变 / 无发光 / 无彩色阴影 | `grep linear-gradient\|box-shadow` 人工过一遍 |

### 可用性

| # | 标准 | 测法 |
|---|---|---|
| **A8** | 正文对比 ≥ 7:1，次要文字 ≥ 4.5:1 | 脚本算 WCAG 比值 |
| **A9** | 每个数据块 0 数据时有「一句说明 + 一个动作」 | 用新账号登录逐块截图 |
| **A10** | 1440 / 1280 / 768 / 430 四档无横向滚动、无文字截断 | `document.scrollWidth <= clientWidth` + 截图 |
| **A11** | 首屏 LCP < 1.5s，CLS < 0.05 | PerformanceObserver 打点 |
| **A12** | Tab 顺序合理、focus 可见、折叠按钮有 `aria-expanded` | 键盘走一遍 + DOM 断言 |

### 与提案的一致性

| # | 标准 | 测法 |
|---|---|---|
| **A13** | 5 项决策逐条落地：① hero 唯一 ② 主图带时间范围 ③ 有「继续上次」 ④ 队列条 = 占今日比例 ⑤ 单一强调色 | 与 `dashboard_v2_proposal.png` 并排核对，逐条打勾 |
| **A14** | 回归不退化：`verify_all` 95/95，9 页 0 JS 报错 | 跑脚本 |

**判定**：A1–A7 全过 + A9–A14 全过 = 通过；A8/A11 若未过需给出原因与改法。

## 五、需要你拍一个板：现有的「AI 卡片看板」怎么办

现在仪表盘是"AI 按主题生成卡片 + 拖拽 / 翻转 / 缩放"。新方案是**固定版式**，两者冲突。三个选择：

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A（推荐）** | 默认 = 新的固定仪表盘；AI 卡片看板挪到「我的看板」二级 tab | 首屏变好，功能不丢 | 多一个 tab，两套样式要维护 |
| **B** | 直接删掉 AI 卡片看板 | 最干净、代码最少 | 丢「按主题生成」这个卖点，后端 `dashboard_layouts` 闲置 |
| **C** | 新仪表盘只做 hero + 主图，下面保留 AI 卡片区 | 改动最小 | 又变成"上面一块下面一片"，节奏还是乱的 |

我建议 **A**：首屏按对标重做，AI 看板作为"自定义视图"保留，用户想折腾再进去。

### v3 相对 v2 改了三处（全部来自对照结论）

| 改动 | 依据 | 结果 |
|---|---|---|
| **三张 KPI 卡 → 一条指标带**（4 指标，竖发丝线分隔） | Plausible 的 6 指标一条带 | 少 2 个卡片边框、少 3 个圆角，一屏从 7 块降到 **5 块** |
| **队列 → 条形表**（浅色条在文字背后，宽度 = 占今日比例） | Plausible 的 Sources / Top Pages | 去掉 3 个独立进度条 + 3 段 meta 文案 |
| **指标带左内边距 20 → 24** | 与 hero 卡对齐 | hero 与指标带文字都从 x=297 起（实测一致） |

实测：一屏 **5 个数据块**、主按钮 1 个、hero 44px / 指标 22px（2.0 倍）。

### 验收标准增补

| # | 标准 | 测法 |
|---|---|---|
| **A15** | KPI 必须是**一条指标带**（≥3 个指标、竖发丝线分隔），不能是并列卡片 | 统计 `.strip .m` 数量 ≥3 且 `.m + .m` 有 border-left |
| **A16** | 队列必须是**条形表**：条在文字背后、宽度 = 占今日比例、数值右对齐 | 截图核对 + `qfill.style.width` 与数值/总数一致 |
| **A17** | chrome 里的强调色 ≤ 2 处（选中指示 + 关键数字）；图表与条形表用同一色值，不引入第二色 | 人工清点并在截图标注 |
