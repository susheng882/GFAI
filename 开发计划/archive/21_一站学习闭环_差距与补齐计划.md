# 21 · 一站学习闭环 · 差距评估与补齐计划

> 输入：产品计划书 / 技术报告的硬性要求 + 本轮真实材料压测 + 市面产品布局调研
> 结论先行：**解析不慢（5.2MB→1.8s），慢的是"生成卡片"（116s/27 张）和"扫描件根本解析不了"**。
> 这两件事直接卡住你"题库→背诵→刷题"的闭环。

---

## 1. 本轮实测（真实材料，`F:\BaiduNetdiskDownload`）

| 样本 | 大小 | 解析 | 卡片生成 | 结果 |
|---|---|---|---|---|
| 《2027王道8套卷》 | 5.2 MB | **1.82s → 429 块** | **116.67s → 27 张** | ✅ 全通 |
| 《数一李林六套卷做题本》 | 9.1 MB | **0.79s → 失败** | — | ❌ 扫描件，无文字层 |

**结论**
1. **解析速度没问题**：2.9 MB/s，5MB 试卷 1.8 秒；瓶颈在入库后的 LLM 生成。
2. **卡片生成是瓶颈**：27 张要 117 秒 ≈ **4.3 秒/张**，且是串行分批。这是"点了没反应"的真正来源。
3. **扫描版 PDF 完全不可用**（你的网盘里这类占多数）。现有 `question_vision` 视觉识别只挂在「题库导入」路径上，「资料解析」路径没有 OCR → 同一个文件换个入口才能用，用户不可能知道。

## 3. 市面产品布局调研（决定"闭环"长什么样）

| 产品 | 值得抄的布局/交互 | 我们缺什么 |
|---|---|---|
| **Anki** | 学习时全屏单卡、四档评分、剩余数、日目标条；卡片浏览器（表格+筛选） | 复习页没"日目标/剩余"；没有卡片管理表格 |
| **墨墨背单词** | 词表 → 今日任务 → 复习/新学 双队列；遗忘曲线可视化 | 没有"今日新学 vs 复习"双队列 |
| **Quizlet** | 学习集卡片网格 + 测试模式 + 配对游戏；进度环 | 刷题与卡片是割裂的两个模块 |
| **Obsidian / Logseq** | 左树 + 中编辑 + 右反链/大纲，**每栏都能收起**；命令面板 | 右栏固定、无折叠；无命令面板 |
| **RemNote** | 笔记里直接做卡片（行内标记），笔记与复习同源 | 笔记与卡片是两套数据 |
| **Notion** | 数据库视图切换（表/看板/日历）、页面属性 | 资料/题库没有多视图 |

**可迁移的三条**（本轮就做）
1. **每栏可收起**（Obsidian 式）：左树、右反链、视频中栏，一键折叠，状态记忆。
2. **卡片浏览器**（Anki 式）：表格 + 按卡包/熟练度筛选 + 批量删除/重置。
3. **闭环状态条**：资料 → 笔记 → 卡片 → 刷题 → 复习，五步进度一眼看到。

## 4. 一站式闭环：现在的断点

```
上传资料 ✅ ──▶ 解析 ✅ ──▶ 笔记 ✅ ──▶ 卡片 ✅ ──▶ 刷题 ⚠️ ──▶ 复习 ✅
                 │              │            │           │
           扫描件 ❌        无"AI 润色/整理"  4.3s/张      必须先有题库
           入口未引导        入口（有接口）   串行拖慢     （新用户会懵）
```

**四个断点**：扫描件、卡片慢、笔记 AI 入口不显、刷题依赖题库无引导。

## 5. 补齐计划（P0 → P2）

### P0（本轮，直接影响能不能用）
| # | 事项 | 做法 | 验收 |
|---|---|---|---|
| 1 | **扫描件 OCR 兜底** | 资料解析检测"无文字层"时，自动切视觉识别（复用 `parse_paper`），逐页 OCR 后走同一分块 | 9.1MB 扫描试卷能出 chunks；耗时 ≤90s |
| 2 | **卡片生成并发** | 分批请求改为并发（受方舟 2 并发限流约束，分批 2 路），失败重试 | 27 张 ≤60s（当前 117s） |
| 3 | **AI 整理/润色入口显性化** | 笔记页顶部加「AI 整理全部 / 润色本篇」，调用已有 `/notes/tidy`、`/notes/ai-suggest` | 点一下能出建议并可应用 |
| 4 | **刷题空态引导** | 题库为空时，按钮改为「导入题库」并跳转 | 新账号不再看到"题库为空"报错 |

### P1（体验闭环）
| # | 事项 | 验收 |
|---|---|---|
| 5 | 各页面**侧栏可收起**（左树/右反链/视频中栏），状态记忆 | 三处都能一键折叠，刷新后保持 |
| 6 | 卡片浏览器（表格 + 筛选 + 批量操作） | 能按卡包/熟练度筛，批量删除生效 |
| 7 | 闭环状态条（资料→笔记→卡片→刷题→复习） | 概览页一眼看出卡在哪一步 |
| 8 | 账号数据导出/注销入口 | 导出 zip 可下载；注销二次确认 |

### P2（上线门禁）
9. 监控告警（失败率/队列积压/成本超阈值）
10. 评测集进 CI（`eval_gate.py` 接 GitHub Actions）
11. 备份恢复演练在产品内可见

## 7. 执行顺序

1. P0-1 扫描件 OCR（最影响你材料可用性）
2. P0-2 卡片并发（最影响体感速度）
3. P0-3/4 入口显性化 + 空态引导（最影响"会不会用"）
4. P1-5 侧栏收起 → P1-6 卡片浏览器 → P1-7 闭环状态条

每完成一项跑一次回归，全绿才进下一项。
