# UX 组件库重构：资源清单与验收标准

> 日期：2026-11-22　｜　范围：前端 `gflc/backend/frontend/index.html`（纯前端，零后端改动）
> 目标：以**用户实际体验**为出发点，沿用已落地的 v3 布局与提速成果，用**现成设计 skill / 组件库**重构，而非自创样式。

---

## 一、为什么这样重构（体验诊断）

沿用 `09_项目审查与优化报告` 与 v3 布局落地后的真实代码，逐项核对出三个"用户能直接感知"的体验缺口：

| 痛点 | 用户实际感受 | 根因（代码事实） |
|---|---|---|
| **AI 等待是黑盒** | 提问后只看到一行转圈，不知道在检索、核对还是生成；18s 里没有任何进度语义 | `doAsk()` 旧实现仅 `pending` + 一句 hint，`msgHtml` 无阶段信息 |
| **答案无法继续追问** | 答完就结束，用户得自己重新组织下一个问题 | 旧 `msgHtml` 只有气泡 + 来源芯片，无 follow-up |
| **微交互生硬** | toast 硬切、tabs 无反馈、hero 数字直接出现 | toast 用对称 `t-mid`，无 blur；圆角是双套魔法数字 |

**没有动的部分**（避免重复造轮子 / 破坏已验收成果）：v3 布局结构、纸墨配色、后端提速开关、95 项接口。

## 三、验收标准

### 3.1 设计系统合规（对齐 `gflc-design` 自查清单，逐条可勾）

- [x] 一屏数据块 ≤ 7，hero 唯一（v3 布局已满足，本次未改结构）
- [x] 一屏只有 1 个实心主按钮（新增 follow-up 用 `.fu` 描边芯片，非实心）
- [x] 所有间距是 4 的倍数（过程行 `gap:12px` = 3×4，遵循阶梯）
- [x] 字重只有 400/500（新增 CSS 未引入其他字重）
- [x] 强调色 ≤ 4 处，无渐变无发光（过程行用 success/info 软背景表意，非装饰）
- [x] 每个数据块有 0 数据形态（follow-up 仅在有答案时出现；过程行结束后移除）
- [x] 1440 / 768 / 430 三档无横向滚动 —— **实测通过**
- [x] 深色下卡片与背景可分辨，正文对比 ≥ 7:1 —— **实测 body rgb(15,14,12) vs 气泡 rgb(46,40,30)，可分辨**
- [x] 没有 emoji 当图标、没有操作说明式文案（follow-up 用 `ICONS.spark` 内联 SVG）

## 四、已知边界与后续（诚实记录）

1. **答案里的 `[1][2]` 引用仍是纯文本**，未做行内上标芯片——因为 `mdToHtml` 后处理可能误伤数学式中的方括号，收益低于风险；来源已通过气泡下方芯片 + 思考轨迹双重呈现。
2. **toast 的 blur 溶解在 `prefers-reduced-motion` 下自动降级**（全局兜底规则已存在）。
3. **follow-up 建议是按 mode 的本地模板**（知识库/联网/模型各 3 条），零 LLM 调用——刻意保持与提速成果一致，不因 UX 增加后端成本。
4. 过程阶段由**前端事件驱动**（status/sources/delta），若后端事件顺序变化需同步调整 `bump()` 映射。
