## 一、组件库选型（减少自写代码）

| 库 | 版本策略 | 用途 | 替换的自写代码 |
|---|---|---|---|
| antd 5.29（已有） | 换肤不改版 | 表格/弹窗/树/表单/开关 | 无（保留） |
| @ant-design/charts | latest | 趋势折线/柱状/分布图 | 自写内联 SVG 图表 |
| framer-motion | ^11 | 入场/抽屉/翻卡/侧栏图标动画 | 手写 keyframes |
| cmdk | ^1 | 命令面板 ⌘K | 自写 CommandPalette |
| @fullcalendar/react + daygrid + timegrid | ^6 | 日历月/周/日三视图 | 原型 c7-*（无 React 版） |
| @ant-design/icons（已有） | 保留 | 图标 | 无 |

**不引入 Tailwind**：原型 token 已提取为 CSS 变量，React 组件用内联 style + 少量 utility class 即可，避免 preflight 与 antd 冲突。

## 二、后端接口设计（阶段 C 新增，全部带测试）

### 2.1 AI 伴侣会话

```
GET    /api/conversations                列表（今天/昨天分组、未读数）
POST   /api/conversations                新建会话 { title? }
GET    /api/conversations/{id}/messages  消息列表（含引用详情）
POST   /api/conversations/{id}/messages  发送消息（流式，复用 /qa/stream 引擎）
     body: { content, context?: { notes?: [id], wrongs?: [id], plans?: [id] } }
DELETE /api/conversations/{id}           删除会话
PATCH  /api/conversations/{id}           重命名 { title }
```

数据模型（迁移 0012）：
```sql
conversations: id, user_id, title, created_at, updated_at
conversation_messages: id, conversation_id, role(user/assistant), content,
                       sources(json), steps(json), created_at
```

### 2.2 成长记录与成就

```
GET /api/achievements                    成就总览
     → { level, xp, xp_next, stats: {days, hours, cards, accuracy, completion},
         abilities: {memory, understand, speed, accuracy, persistence},
         milestones: [{name, done, at}] }
```

数据来源：纯聚合现有表（review_logs/attempts/cost_ledger/cards），不建新表。

### 2.3 计划日历

```
GET  /api/plans/events                   日历事件（月/周/日，返回 [start,end,title,plan_id,done]）
POST /api/plans/tasks                    新建计划任务 { title, due_at, plan_id? }（兼容现有 plan_tasks）
```

### 2.4 通知

```
GET  /api/notifications                   通知列表（到期卡片/解析完成/连续达标）
POST /api/notifications/{id}/read         标记已读
```
数据来源：实时计算（到期卡片数、最近完成 task、streak），不落库。

### 2.5 工作区

```
GET    /api/workspaces                    工作区列表（408/英一/数一）
POST   /api/workspaces                    新建工作区 { name }
PATCH  /api/workspaces/{id}               切换当前 { current: true }
GET    /api/workspaces/current            当前工作区
```

数据模型（迁移 0012）：
```sql
workspaces: id, user_id, name, current(bool), created_at
```
数据隔离：documents/notes/cards/questions/plans 增 workspace_id 列（可空，空=全局）。
**渐进策略**：先落表+接口，数据迁移（把现有数据归入默认工作区）在 C8 验收时做。

### 2.6 解析保存路径

```
POST /api/questions/import 增参数 { folder_path?: string }  → 题库归属路径
GET  /api/questions/folders               文件夹树（供 pickPath 弹窗）
```

### 2.7 诊断

```
GET /api/settings/diagnostics  已有，扩展 7 项：ffmpeg/whisper/cookie/providers/vector/ocr/disk
```

## 五、执行纪律（每个 Agent 必守）

1. 只改自己批次的文件；跨文件（App.jsx/theme）改动需注明并说明理由
2. 每完成一个子任务：build + 相关测试立即跑
3. 交付时输出：改动的文件清单 + 门禁结果 + 已知限制
4. 三次失败暂停求助，不隐瞒错误
5. 不引入新依赖库以外的 npm 包；装新包前在主线程报备

| 风险 | 概率 | 对策 |

| antd 换肤后旧页面视觉错乱 | 高 | 分批对齐，主题先行，旧页面暂用兼容变量 |
