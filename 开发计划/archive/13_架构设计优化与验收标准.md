## 一、本次已修复的设计缺陷（代码已改 + 已回归）

> 判定标准：改前与改后的**默认值完全相同**，只是把"散落/硬编码/静默"变成"单一真源/可配置/可见"。

### 1.1 D3　置信度量纲三套并存 → 统一到 config 单一真源

| 项 | 改前 | 改后 |
|---|---|---|
| 相关线 | `query_opt.RELEVANT_SCORE = 3.0`（硬编码，0–5 分域） | `settings.QA_MIN_CONFIDENCE × 5`，默认 `0.6×5=3.0`（**数值不变**） |
| 覆盖率兜底 | `qa._MIN_COVERAGE = 0.34`（硬编码） | `settings.QA_COVERAGE_FLOOR`，默认 `0.34`（**数值不变**） |
| 废弃字段 | `RETRIEVAL_SCORE_THRESHOLD=0.7` 定义了但从未被检索使用，误导读者 | 改名为 `QA_MIN_CONFIDENCE=0.6`，旧字段标注 deprecated 留兼容 |

- **为什么重要**：三套量纲（0.7 / 3.0 / 0.34）让人无法判断"到底多少分算命中"，调参时改一个不生效是隐蔽陷阱。
- **改动文件**：`app/core/config.py`、`app/services/query_opt.py`、`app/routers/qa.py`、`deploy/.env.example`
- **回归证据**：`RELEVANT_SCORE==3.0`、`QA_COVERAGE_FLOOR==0.34` 断言通过；`verify_all` 中 knowledge 问答模式通过。

### 1.2 D4　成本护栏双份配置漂移 → budget 回落 config 单一真源

| 项 | 改前 | 改后 |
|---|---|---|
| config.py | `DAILY_TOKEN_QUOTA=20000`、`DAILY_COST_LIMIT_CNY=250`（**budget 从不读，纯摆设**） | 新增 `DAILY_USER_TOKENS=300000`、`DAILY_USER_COST_CNY=2.0`、`SINGLE_TASK_TOKENS=60000`、`BUDGET_ENABLED=true` |
| budget.py | 自己硬编码 `300000 / 2.0 / 60000` | 先读同名 env，未设置回落 `settings.*`（**默认值不变**） |
| 语义澄清 | `MAX_TASK_TOKENS` 与预算上限混在一起 | 明确 `MAX_TASK_TOKENS` 是单次生成 max_tokens（deepseek 用），与 `SINGLE_TASK_TOKENS` 不同 |

- **为什么重要**：报告要求"日成本超预算 120% 自动降档"，但 config 里写 250 元、budget 实际用 2 元——两处真相导致告警阈值永远算错。
- **回归证据**：`budget.limits()` 实测返回 `{daily_user_tokens:300000, daily_user_cost_cny:2.0, single_task_tokens:60000, enabled:True}`，与改前一致；env 覆盖能力保留。

### 1.3 D6　800 块静默截断 → 可配置 + 触顶告警

| 项 | 改前 | 改后 |
|---|---|---|
| 上限 | `_chunk_stmt` 硬编码 `LIMIT 800` | `LIMIT settings.RETRIEVAL_MAX_CHUNKS + 1`（默认仍 800） |
| 触顶行为 | **静默丢弃**超出的块，用户以为全量可检索 | 多取 1 条用于检测，触顶打 `WARNING`（带 user/doc 维度），检索结果不变 |

- **为什么重要**：技术报告要求"禁止静默失败"；一个重度用户上传超过 800 块后，尾部资料永远召不回且无人知晓。这是数据一致性隐患，不是性能问题。
- **改动文件**：`app/services/rag.py`、`app/core/config.py`、`deploy/.env.example`
- **回归证据**：编译通过；SQL 编译参数实测 `param_1=801`（cap+1）；95/95 通过。

### 1.4 D11　拒答判定字符串匹配散落 4 处 → 单一入口

| 项 | 改前 | 改后 |
|---|---|---|
| 判定 | `any(k in answer for k in _REFUSAL)` 在 `qa.py` 出现 4 次（510/529/541/716 行附近） | 统一到 `_is_refusal(answer)` 一个函数，4 处调用它 |

- **为什么重要**：报告要求"策略切换可解释、结构化"。当前靠自然语言关键词判断"该不该转联网"，脆弱且分散；集中到一处后，未来替换为模型结构化拒答标志或 confidence 字段只改一行。
- **诚实边界**：**本次没有把关键词匹配换成结构化信号**——那需要改模型输出契约并跑评测集验证，属"欠账"而非"无风险修复"，列在第二节。
- **回归证据**：`_is_refusal()` 对 4 组样本判定与旧逻辑一致；`verify_all` 的 knowledge/web/hybrid/stream 问答全通过。

### 1.5 D1　dev/prod 栈混用静默 → 启动一致性自检

| 项 | 改前 | 改后 |
|---|---|---|
| 启动检查 | 无 | `main.py` lifespan 调用 `_check_runtime_consistency()`：APP_ENV=prod 时逐项检查 DEV_MODE / COOKIE_SECURE / STORAGE_BACKEND / DATABASE_URL / SESSION_SECRET，冲突项打 ERROR |

- **为什么重要**：本机 SQLite 全绿、上线用 pgvector 必炸，是评审里"代码—文档双轨制"的根源。现在生产配置带着 dev 残留启动会留下显式错误日志。
- **诚实边界**：只告警**不阻断**——强行 raise 会破坏本机 dev 与现有验收流程；真正的阻断放在上线门禁 Go/No-Go（第四节）。
- **回归证据**：dev 模式只输出 INFO 提示；模拟 prod + 4 项 dev 残留，实测输出 4 条 ERROR + 汇总 ERROR。

### 1.6 本次改动清单（可审计）

| 文件 | 改动 |
|---|---|
| `app/core/config.py` | 成本护栏 4 字段 + 置信度 2 字段 + `RETRIEVAL_MAX_CHUNKS`；旧字段标废弃 |
| `app/core/budget.py` | `limits()` / `enabled()` 回落 settings；env 覆盖保留 |
| `app/services/query_opt.py` | `RELEVANT_SCORE` 由 `QA_MIN_CONFIDENCE×5` 派生 |
| `app/services/rag.py` | 上限可配置 + 触顶 WARNING |
| `app/routers/qa.py` | `_is_refusal` 集中化；`_MIN_COVERAGE` 走 config |
| `app/main.py` | `_check_runtime_consistency()` 启动自检 |
| `deploy/.env.example` | 成本护栏/置信度/上限字段同步，注释写清口径 |

## 二、不建议现在动的设计缺陷（附触发条件）

> 这些是**架构级或质量级**改动。评审报告已明确顺序：**评测集 → 双路召回 → 架构升级**。
> 没有评测集就动它们，等于把质量退化盲目送上线。此处给出"何时可以动"的触发条件，不写代码。

| 编号 | 缺陷（来自评审 12） | 为什么现在不动 | 触发条件 / 前置 |
|---|---|---|---|
| D5 | BM25 单路，语义问法召回不到 | 需引入 embedding 模型，改变检索主链路；无评测集无法证明不退化 | 先建 N5 评测集基线（≥30 资料 + 20 问），再上 sqlite-vec + bge-small 双路 |
| D7 | chunks 与 notes 两套索引未统一 | 需改写入路径与 `source_type`，属数据结构变更 | 有 Alembic 迁移 + 评测集回归后可做 |
| D8 | 视频三通道未对齐、无网格拼图 | 改动大且依赖外部模型；现有 OCR 并发已缓解超时 | 字幕优先取材（A1）先落地并测量收益后再决定 |
| D9 | 转写 quality=low 仍写 ready | **行为改变**（low 不再 ready 会影响现有 95 项中视频用例） | 需先定"待确认队列"产品形态 + 评测集，再改状态机 |
| D10 | 计划页移出导航、仪表盘未打通 | 前端产品决策（入口放哪），不是纯设计缺陷 | 产品确认"今日任务卡"数据源与交互后 |
| D12 | 单文件 2849 行 | 拆分风险高、收益是长期可维护性，非上线阻断 | 上线后按页面拆 module，配 CI 行数门禁 |
| V1/V2 | 向量检索缺失、队列未分进程 | 架构级大改，需生产栈联调 | 走 10 号计划阶段 A/C，三容器冒烟通过 |

## 三、验收标准：每条不足对应一条可测门

> 格式：编号 / 对应不足 / 判定标准（可测、有分母、有测法）/ 等级。
> 等级：**V**=一票否决（不满足禁止发布）、**M**=强制（需书面豁免）、**S**=建议。

### 3.1 本次修复项的回归门（本次已通过，后续每次提交须保持）

| 编号 | 对应不足 | 判定标准 | 测法 | 等级 |
|---|---|---|---|---|
| A1 | D3 量纲漂移 | `RELEVANT_SCORE == QA_MIN_CONFIDENCE × 5` 且默认 = 3.0；`QA_COVERAGE_FLOOR` 默认 = 0.34 | 单元断言（`config` + `query_opt`） | M |
| A2 | D4 护栏漂移 | `budget.limits()` 四项与 `settings` 同名值一致；设 env 后覆盖生效 | 单元断言 + env 注入测试 | M |
| A3 | D6 静默截断 | 语料数 = 801 时日志出现 `retrieval corpus truncated`，且检索仍只返回前 800 | 造 801 chunk 的集成用例 | M |
| A4 | D11 拒答分散 | 源码中 `_REFUSAL` 仅出现在 `_is_refusal` 函数体内（grep 计数 = 1 处逻辑） | `grep -n` 静态检查 | S |
| A5 | D1 栈混用 | APP_ENV=prod + 任一 dev 残留 → 启动日志出现对应 ERROR | 模拟配置单测（已实测通过） | M |
| A6 | 全局不回归 | `verify_all.py` 退出码 0 且 `通过 95/95`；前端 JS `new Function` 无异常 | 回归脚本 + node 语法检查 | V |

### 3.2 架构级欠账的门槛（未达不得上线，达了才允许进入下一阶段）

| 编号 | 对应不足 | 判定标准 | 测法 | 等级 |
|---|---|---|---|---|

| N9 | D9 低质转写入库 | `quality()` 返回 low 时不写 ready，进入待确认队列并标低置信 | 低质音频用例 | M |

### 3.3 体验与速度的持续门（沿用评审 12 的 P/F 系列，不重复列出）

- 问答：首字节 ≤1s；端到端 P95 ≤8s（目标 ≤5s）；检索环节 ≤1s。
- 视频：有字幕视频 1h 出大纲 ≤3min 且 Whisper 调用 = 0；完整图文笔记 ≤8min。
- 不静默失败：排队超时、解析部分失败、超限三类均有明确提示与下一步动作。
- 质量不退化：任一质量指标版本间降 >3pp 即回滚，无例外。

## 五、复现与验收命令

```bash

  app/services/query_opt.py app/services/rag.py app/routers/qa.py app/main.py

# 2. 单源与行为保持断言（需先启动依赖环境）
python - <<'PY'

assert query_opt.RELEVANT_SCORE == 3.0
assert budget.limits()["daily_user_cost_cny"] == 2.0

print("OK")
PY

# 3. 拒答集中化静态检查（_REFUSAL 只应在 _is_refusal 内被遍历）
grep -n "for k in _REFUSAL" app/routers/qa.py   # 期望仅 1 行

# 4. 全量回归（服务需在 8010）
python scripts/verify_all.py        # 期望：通过 95/95，退出码 0

# 5. 前端语法
node -e "const fs=require('fs');const h=fs.readFileSync('frontend/index.html','utf8');\
const m=h.match(/<script>([\s\S]*)<\/script>/);new Function(m[1]);console.log('OK')"
```

**本次实测结果（2026-11-22）**：编译通过；单源断言全部通过；`grep` 仅 1 处逻辑；`verify_all` **通过 95/95、退出码 0**；前端 JS 语法 OK；启动一致性自检 dev/prod 双场景输出符合预期。
