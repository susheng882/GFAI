# 23 · 多 Agent 续开发执行计划（学习闭环 + 市面布局对齐）

> 制定时间：2026-11-23　｜　状态：Wave 1 执行中　｜　前置契约：`14_多Agent开发约束与硬门禁.md`、目标基线：`21_一站学习闭环_差距与补齐计划.md`
> 一句话：把「资料 → 笔记 → 卡片 → 刷题 → 复习」的每个断点按波次修完，同时把市面学习软件的布局骨架和交互逻辑借过来，变成 GFLC 自己的纸墨风格。

## 0. 执行原则

1. **借布局，不抄皮肤**：只借鉴 Anki / Quizlet / 墨墨 / Obsidian / RemNote / Notion 的信息架构、操作路径和状态反馈；不复制像素、图标、品牌文案。所有视觉落到 `gflc-design` 的 token 与类名。
2. **文件所有权隔离**：每个 Agent 只改自己独占的路径；发现别人改了自己的文件立即停止并报告，绝不强行覆盖。
3. **自测与集成分离**：Agent 只做编译级、纯函数级、独立临时 DB 级自测和 `npm run build`；**禁止启动 8011 服务、禁止跑 `verify_all.py`、禁止改 `.env`**。全量回归由集成方统一执行。
4. **外部契约只增不改**：`/api/*` 已有字段不删不改类型；新字段必须可选或带默认值。
5. **零静默失败**：降级、截断、超时、OCR 失败都要有日志（带 document_id / task_id）或 API 可见原因。
6. **0 数据形态**：每个新增数据块在空数据时必须有「一句说明 + 一个可点动作」，不能只给空表格。

## 2. Wave 1（本轮并行，4 个 Agent）

| Agent | 独占路径 | 任务 | 完成判定 |
|---|---|---|---|
| `layout-research` | `开发计划/22_市面学习闭环布局对标规范.md`（仅此新建文件） | 实际检索 6+ 产品，产出逐页布局规范与验收清单 | 文档含来源 URL、逐页映射、可勾选清单 |
| `ocr-backend` | `app/services/{parse,question_vision,pipeline}.py` | 无文字层 → 逐页 OCR → 同一分块入库；错误可见 | 9.1MB 扫描件 chunks>0 且 ≤90s |
| `loop-api` | `app/routers/dashboard.py`、`app/services/mastery.py` | 五步闭环状态接口，返回计数/阻塞/跳转 | 空账号安全返回，字段只增不改 |
| `fe-loop` | `gflc/web/**` | 侧栏折叠记忆、卡片浏览器、闭环状态条、AI 入口、刷题空态、导出/注销入口、复习页增强 | `npm run build` 通过，设计系统自查全绿 |

**并行协议**：四个 Agent 同时开工，互不读改写对方文件；接口契约由 `fe-loop` 按本文约定的 `GET /api/dashboard/loop` 接入，接口 404 时前端降级显示占位而非白屏。

## 6. 风险与回滚

| 风险 | 处理 |
|---|---|
| 多 Agent 同时改同一文件 | 所有权表硬隔离；集成方合并前先逐文件 `git diff` 检查 |
| 方舟账号并发上限 2 导致 429 | 沿用信号量 + 退避，不提高并发 |
| 扫描件视觉识别质量不稳定 | 失败页打日志并可重试；不把部分失败写成整体成功 |
| 卡片吞吐仍 >60s | 如实记录 76s 基线与瓶颈（方舟 2 并发），给「缓存/模板化」下一步方案，不虚报达标 |
| 前端改造破坏既有页面 | 构建 + 95/95 回归 + 三档视口截图逐项核对 |
| 回滚 | 集成方合并前对目标文件做 `.bak` 备份；回滚只还原该文件，不动其他 Agent 产物 |
