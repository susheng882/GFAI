## 0. 口径与合规边界（先读）

1. **只借鉴交互逻辑与信息结构，不复制像素、图标、品牌文案。** 粉笔的「智能组卷」、猿题库的「能力评估报告」、医考帮的「快刷模式」等均为竞品术语，GFLC 落地时统一改写成自己的中文表述（组卷→「按条件出题」，报告→「练习报告」，快刷→「快速过题」）。**不做同名词照搬。**
2. **不引入新视觉 token。** 所有借鉴项落到 GFLC 既有纸墨风格：卡片 `#fdfbf7`、发丝线、强调 `#1f4d6b`、荧光笔只标唯一 hero 数字、图标走 `ICONS` 内联 SVG 18px/1.5 stroke、禁 emoji、字重仅 400/500、间距 4 的倍数。
3. **不声称已实现。** 「GFLC 是否已有」以本次只读核对的 `StudyPage.jsx`（刷题/测试/错题本三态）与 `quiz.py`（7 个接口）为准，代码里没有就写「❌ 无」。
4. **唯一允许新建的文件是本文**；不改 `.jsx`、不改 CSS、不改 API 契约、不启服务、不 git 提交。
5. 竞品官网的内容营销页（`fenbi.com/page/information-hub-detail/*`）大量使用「具体功能以当期为准」的免责口径，本文引用其**功能存在性与维度清单**，不引用其价格、命中率、用户量作为产品承诺。

## 3. 三类刷题页的布局骨架对比

> 只描述**区块层级**与**信息密度**，不涉及像素、配色、图标。信息密度按「一屏可见的数据块数量」粗略分档：低 ≤3、中 4–6、高 ≥7（GFLC 硬规则：一屏 ≤7）。

### 3.1 做题页（答题态）

| 维度 | 竞品骨架（粉笔 / 医考帮 / 考研帮） | GFLC 现状 | 差距判断 |
|---|---|---|---|
| 顶部条 | 左：`第 n / N 题` + **已用时长 / 剩余时长**；右：**答题卡入口**（一个按钮或图标）、交卷/退出 | `第 n / N 题` + 「结束练习」文字按钮（`StudyPage.jsx:208-211`、`:299-302`） | 缺计时、缺答题卡入口 |
| 主数据区 | 题干（大字号）→ 选项（单选圆点 / 多选方框 / 填空输入） | 题干 + 选项块（`:212-225` / `:303-321`） | 基本对齐；test 态多选交互已正确（`:309-318`） |
| 底部操作 | `上一题` / `下一题` / **`交卷`**（最后一题或任意时刻可交）；练习模式则「提交」即判 | quiz 态：提交→下一题；test 态：上一题/下一题/交卷评分（`:322-330`） | 结构齐，缺「随时交卷」与「未答提示」 |
| 答题卡 | **浮层/抽屉**，题号格子四态：未答 / 已答 / 标记疑题 / 当前题；点格子跳题；底部「交卷并查看结果」（粉笔，第三方部分查证） | ❌ 无 | **最大结构缺口** |
| 信息密度 | 低（一屏一题，答题卡是二级浮层，不抢主线） | 低（一致） | — |
| 侧栏 / 辅助 | 收藏、笔记、纠错、答疑入口（医考帮/粉笔） | 无 | P2 |

**骨架建议（自上而下）**：
1. 顶条：`第 n / N` + `用时 mm:ss`（或剩余）+ `答题卡`（次级按钮）+ `交卷`（仅 test 态为主按钮）
2. 题干区（唯一 hero 级文本）
3. 选项区
4. 底部：`上一题` / `下一题`（次级），最后一题时 `交卷` 变主按钮
5. 答题卡浮层：题号网格 + 图例（未答/已答/疑题）+ 交卷

## 4. GFLC 缺失清单（按优先级）

> 成本口径：**低** = 1–2 天纯前端；**中** = 3–5 天含联调或后端小改；**高** = 数据模型/算法改造（≥1 周）。
> 「需后端新接口」列：**否** = 复用现有 `/quiz/generate`、`/quiz/submit`、`/quiz/wrong`、`/quiz/chapters`；**小改** = 同接口加 query 参数/返回字段（不算新接口）；**是** = 需新增路由或表字段。

| # | 缺什么 | 竞品依据 | 实现成本 | 需后端新接口 | 优先级 |
|---|---|---|---|---|---|
| 1 | **答题卡**：题号网格、四态（未答/已答/疑题/当前）、点格跳题、底部交卷 | 粉笔（haoruan 第三方）/ 考研帮（bkili 第三方）/ 刷刷题（第三方，佐证通用性） | **低**（`test.qs` + `test.answers` 已在前端，纯渲染） | **否** | **P0** |

## 5. 建议落地顺序（只给顺序，不给排期）

1. **P0-a 答题卡 + 随时交卷**：test 态加题号浮层，四态 + 跳题；`交卷` 从「最后一题」放宽到常驻。

3. **P0-c 知识点分布**：结果页在得分卡下加一段「按章节正确率」，用 `Progress` 细条 + 文本（`12/20 · 60%`），不引图表库。
4. **P0-d 错题重做**：错题列表每条加「重做」，答对后 `message.success('已移出错题本')` 并刷新 `/quiz/wrong`。
5. **P1-a 错题筛选 + 错次展示**：`/quiz/wrong` 加 `chapter` / `qtype` 参数，前端加筛选条。
6. **P1-b 打印/导出**：结果页与错题本加「打印」，`@media print` 隐藏导航与按钮。
7. **P1-c 组卷难度 + 背题模式**：`/quiz/generate` 加 `difficulty`；背书式快速过题。
8. **P1-d 显式移出 + 错因标签**：`wrong_archived` 字段与 `error_tag` 字段（这两项动模型，单独排）。

## 7. 结尾

### 7.1 改了哪些文件

- 未修改任何其他文件，未启服务，未改 `.env`，未 git 提交。

### 7.2 核心结论（5 条）

1. **刷题环节的真正缺口不是「能不能出题」，而是「能不能算一次完整考试」**：GFLC 已有 `/quiz/generate` + `/quiz/submit` + 测试态三段式，但缺**答题卡 + 计时 + 知识点分布**三件套，导致「交卷」只是「把 N 道题连做一遍」。
2. **五项重点缺口里，四项可零后端接口实现**：答题卡、计时、知识点分布、错题重做均可复用现有四个接口，成本为「低」，这是本期性价比最高的改造。
3. **错题本「移出」机制其实已经存在，只是不可见**：`/quiz/wrong` 只返回「最近一次仍错」的题（`quiz.py:263`），答对即自动移出；缺的是**单题重做入口**与**答对后的显式反馈**，不是数据模型。
4. **知识点维度不需要新表**：`Question.chapter` 与 `analysis.point` 已在 `generate`/`submit` 的返回里，前端 `reduce` 即可出「按章节正确率」，不必照抄竞品的雷达图（也符合 22 号「本期不新增图表」）。
5. **竞品的「排名、社区、押题、AI 预测分」不应移植**：这些依赖同场用户数据或内容生态，与 GFLC 单机学习工作台定位冲突；真正可迁移的是**交互节奏**——练习/模考分离、答题卡全局感、错题越用越精。
