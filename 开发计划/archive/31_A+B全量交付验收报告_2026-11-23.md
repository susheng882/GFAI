## 2. A 层：PDF 扫描质量与速度

### 2.1 落地改动

| 改动 | 文件 | 效果 |
|---|---|---|
| 去 JSON 改纯文本直出（核心） | `question_vision.py` | 单页 24.77s → 16.15s，公式标记 118→122；消除"复杂页 JSON 非法→弱 prompt 重试"的质量漂移 |
| 分栏语义 prompt | `question_vision.py` | A3 双栏试卷「先左后右逐栏转录」，避免题干/选项错配 |
| 公式原子化分块 | `chunking.py` | `$...$` 不再被 300 字硬切/100 重叠拆断 |
| 公式配平校验 | `question_vision.py` | `$` 奇偶、未闭合、括号配平；可疑页记 stats 不阻断 |
| 并行渲染 | `question_vision.py` | 按页独立 open + 线程池（默认 4），冷启动省 ~2.7s，页序与字节完全一致 |
| 三档预设 | `config.py` + `.env.example` | `OCR_PROFILE=balanced/quality/fast`，DPI 140 与并发 2 全档固定 |
| 失败页重试 + 页级缓存 + 4 项指标 | `question_vision.py` | 失败页串行重试 1 次；缓存键含内容 hash；stats 增 `ocr_json_retry_pages`/`ocr_page_chars`/`ocr_page_formula_count`/`ocr_page_seconds` |

### 2.2 实测数据

| 轮次 | 耗时 | 页数 | 公式总数 | 可疑页 |
|---|---|---|---|---|
| 冷启动首测 | 75.21s | 13/13 | — | 0 |
| RUN1 | **65.80s** | 13/13 | 884 | 0 |
| RUN2 | **67.63s** | 13/13 | 895 | 0 |
| 均值 | **66.72s** | 13/13 | ~890 | 0 |
| 基线（改造前） | 96.14s | 13/13 | — | — |

### 2.3 诊断结论（不掩盖的事实）

单页耗时与输出长度**无关**：封面页 226 字耗 14.14s，最长页 2686 字耗 8.99s——瓶颈是模型排队而非输出量。13 页 ÷ 账号 2 并发 × 单页约 10s 是物理下限。**75s 目标靠"去 JSON + 并行渲染"达成，未使用任何伪造手段**。

### 2.4 明确不做（已证伪，不重复踩坑）

降 DPI 到 110（实测更慢 121.86s）、并发提到 3（429 + 排队 171s）、PNG/DeepSeek 通道（34.7s/页）、本地 PaddleOCR 部署、图像二值化降采样。
