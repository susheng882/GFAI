## 1. V3 / N5：离线评测集与六指标回归

### 1.1 实现

| 文件 | 作用 |
|---|---|
| `gflc/backend/evals/build_corpus.py` | 一次性生成 32 份真实中文标注资料（可重复运行） |
| `gflc/backend/evals/corpus/*.json` | 32 份资料，按 `pdf / video / note / question_bank` 四类切块，chunk 带 `chunk_id` 与 `page` / `ts_start` |
| `gflc/backend/evals/questions.json` | 24 条标注问题：20 条有答案 + **4 条无答案诱饵** + **3 条语义问法**（「记住公式」→「推导过程」等），逐条标注 `expected_chunk_ids` / `expected_chunk_keywords` / `expected_answer_points` |
| `gflc/backend/evals/offline_eval.py` | 离线评测引擎：中文二元组分词 + 本地语义扩展表 + IDF 打分；**零外部依赖、不调用 LLM** |
| `gflc/backend/scripts/quality_eval.py` | 扩展为**默认离线回归**；`--online` 保留原有在线时延/成本评测，`httpx` 改为按需导入 |
| `gflc/backend/evals/reports/v1.0/report.{json,md}` | 按版本号归档的机器可读 + 人读报告 |

语料分布（实测）：`pdf 10 / video 8 / note 8 / question_bank 6 = 32`；
问题分布：`24 条（诱饵 4、语义问法 3）`。每份资料内容均不同，覆盖数学、英语、学习方法、物理、化学、生物、气候、题库解析等，无占位文本。

### 1.2 验证命令与结果

```bash
cd gflc/backend
python -m py_compile scripts/quality_eval.py evals/offline_eval.py evals/build_corpus.py
python scripts/quality_eval.py --offline --version v1.0
```

实际输出（Python 3.13，**无 httpx / 无 API key** 亦可运行）：

```
离线评测 v1.0（llm_called=False）
语料：32 份资料 / 24 条问题（诱饵 4、语义问法 3）
----------------------------------------
召回率       85.00
命中率      100.00
MRR         95.00
忠实度       82.50
拒答准确率    100.00
卡片可用率     95.00
----------------------------------------
JSON 报告：.../evals/reports/v1.0/report.json
MD  报告：.../evals/reports/v1.0/report.md
```

指标口径（离线可复现代理指标，详见 `offline_eval.py` 文档字符串）：
召回率＝命中期望 chunk 数/期望 chunk 总数；命中率＝top-K 至少命中 1 个期望 chunk；MRR＝首个期望 chunk 排名倒数；
忠实度＝答案要点在被引证据块中可文本证实比例；拒答准确率＝诱饵正确拒答 + 有答案题正确作答占比；
卡片可用率＝能用检索证据生成「问题+要点+来源」完整卡片的题目占比。

语义问法抽检（`report.json.per_question`）：`q-14` 命中 `video-04-c1`（推导过程）、`q-16` 命中 `video-04-c1` / `pdf-01-c1`（求根公式来自配方）、`q-15` 命中 `video-03-c1/c2`（费曼/以教促学）。三条均召回语义相关块，证明本地扩展表对「语义问法召回不到自己资料」这一差异（D5）可离线回归。

> 说明：离线六指标是**确定性代理指标**，不替代线上真实 LLM 答案质量抽检（N6）。两者需分别记录，不可互相顶替。

### 1.3 CI 门禁（`eval_gate.py`）

```bash
python scripts/eval_gate.py --prev evals/reports/v1.0/report.json --curr evals/reports/v1.1/report.json
python scripts/eval_gate.py --reports-dir evals/reports      # 自动取最新两版
```

实测（自造相邻版本报告，仅用于门禁自测，未写入归档目录）：
- 六项指标持平 → `exit=0`，输出「门禁通过」；
- 将「忠实度」人为下调 5pp → `exit=1`，输出 `忠实度 -5.00pp FAIL` + 「禁止打 tag / 禁止发布」。

集成方绑定方式：在打 tag 的 CI 步骤前执行上述命令，`exit≠0` 即中断。`--drop-pp` 默认 3.0，对应技术报告「任一指标下降 >3 个百分点即回滚」。

## 2. V4：HTTPS / Cookie Secure / HSTS

### 2.1 实现

- `deploy/nginx-ssl.conf.example`：80→443 全量 301；TLSv1.2/1.3；`Strict-Transport-Security: max-age=31536000; includeSubDomains`；`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`；流式问答 `proxy_buffering off`；`/docs` 等 403。
- `deploy/docker-compose.ssl.yml`：只读挂载 `./certs → /etc/nginx/certs` 与 `./nginx-ssl.conf → /etc/nginx/conf.d/default.conf`；注入 `COOKIE_SECURE=true`、切换 `CORS_ORIGINS`；80/443 同时暴露。

## 3. V6：备份 / 校验 / 恢复与演练

### 3.1 实现

- `gflc/scripts/backup_restore.py`：`backup` / `verify` / `restore` 三个子命令，覆盖 **SQLite 数据库 + 对象存储目录**；
  - SQLite 用 `sqlite3.Connection.backup()` 在线安全备份，避开 WAL 拷贝不一致；
  - 目录用 SHA-256 逐文件指纹清单（`manifest.json`），`verify` 按清单重算比对；
  - `restore` 必须显式 `--confirm` 才写盘，且先把当前 db / 目录另存为 `.pre-restore-<时间戳>`；全命令支持 `--dry-run`。
- `gflc/scripts/drill.sh`：备份 → 校验 → 破坏（仅临时目录）→ 恢复 → 校验 → 输出 RPO/RTO 计时模板。

### 3.2 验证命令与结果

```bash
python -m py_compile gflc/scripts/backup_restore.py
bash gflc/scripts/drill.sh
```

本机演练输出摘要：
```
样本：db 初始 3 行，storage 2 个文件
[verify] db app.db: 一致 (2a9d69...)
[verify] storage: 一致 (2 文件 / 48 字节)
已模拟破坏：drop table + 清空对象存储（破坏后 docs 表数量=0）
[restore] 已保留恢复前副本：app.db.pre-restore-...
演练结果：备份校验通过 / 破坏成功 / 恢复后 3 行 + 2 文件，一致 ✔
| RPO | 同一时刻备份，≈0（不代表生产） | ______ | ≤24h |
| RTO | 10.59 秒（样本 db）             | ______ | ≤4h（回滚 ≤10min） |
```

演练全程在 `mktemp -d` 临时目录进行，未触碰真实 db / 上传目录；脚本不执行递归删除，临时目录路径已打印供人工清理。

### 3.3 门禁声明

**本机演练只提供「本机参考值 + 生产需复演」**：样本 db 远小于生产库，且未经过 MinIO / pgvector / Redis 三容器栈。
**不得在文档或答辩材料中写「G4 已通过」**。生产 RPO/RTO 实测值与回滚计时必须在服务器上复演后填入上表「生产实测值」列（见 §6）。

## 4. N4：生产栈冒烟（静态部分）

### 4.1 实现

- `gflc/deploy/smoke.sh`：`static`（compose 静态校验，daemon 未启动也能跑）、`live`（容器健康检查清单 + 接口冒烟）、`stress`（20 并发压测入口）三种模式；**不执行 `docker compose up`**。
- `gflc/deploy/stress_20.py`：纯标准库 20 并发压测，输出总数/错误率/平均延迟/P95，默认 `--seconds 600`（10min）、错误率阈值 2%、P95 阈值 3s；绕过 `HTTP_PROXY` 以免本机压测被代理劫持。

### 4.2 验证命令与结果

```bash
bash gflc/deploy/smoke.sh static
# 输出：基础栈 config 通过 / HTTPS 覆盖层 config 通过；临时 .env 自动清理

python gflc/deploy/stress_20.py --url http://127.0.0.1:8765/ --concurrency 20 --seconds 3 --p95-limit 10
# 本机参考：总请求 22 / 错误 0 / 错误率 0.00% / P95 4.181s → 脚本通过路径可用
```

> 本机单请求往返约 0.25–0.35s（沙箱网络开销），20 并发 P95 约 4s，**不能代表生产栈性能**。
> 生产需在灰度环境用真实 `docker compose up` 后的服务复测，阈值按 20 并发 10min 错误率 ≤2%、P95 ≤3s 判定。

### 4.3 三容器/五服务健康检查清单（`smoke.sh live` 模式）

| 层 | 服务 | 检查方式 | 期望 |
|---|---|---|---|
| data | db (pgvector) | `docker inspect` health / `pg_isready` | healthy |
| data | redis | `redis-cli ping` | healthy |
| data | minio | 容器 running + 9000 可访问 | running |
| app | app | `/health` HTTP 200 | healthy |
| 网关 | nginx | `/health` 200、`/` 返回 HTML、`/docs` 403 | running |

线上终态判据（`10_真上线实施计划.md` N4）：`app/data/nginx` 全绿，20 并发 10min 错误率 ≤2%。**当前因 daemon 未启动，live 与 stress 的生产判定未完成。**
