## 0. 结论先行

**这轮不该再加功能，该做「减法 + 接线」。**

| 维度 | 核心判断 | 一句话依据 |
|---|---|---|
| **战略** | 定位收敛为「资料转物料」，放弃与词库/题库比拼 | 竞品靠内容量取胜，我们靠转化率取胜；两头都要必然两头都弱 |
| **技术** | 先清「假完成」与「双轨制」，再谈新能力 | 空壳接口 + 两套掌握度，会让后续所有 AI 能力建在流沙上 |
| **体验** | 五条断边接线，优先于任何新页面 | 用户走完五步，数据不叠加 → 感知不到闭环 |
| **审美** | 从「堆信息」转向「留白 + 一个焦点」 | 仪表盘现有 11 个数据块，设计系统红线是 ≤7 |

## 1. 战略层

### 1.1 定位收敛（必须先拍板）

**建议定位**：把你手上的资料，变成能背、能练、能复习的东西。

| 维度 | 现状问题 | 收敛后 |
|---|---|---|
| 像什么 | 既像学习工作台、又像资料工具、还像背单词解药 | 一句话能说清：**资料 → 物料** |
| 比什么 | 和墨墨比背词、和粉笔比题库 | 和「手工做 Anki 卡」比效率 |
| 护城河 | 功能数量（易被抄） | **PDF/视频 → 结构化物料的转化质量与速度**（难被抄） |

### 1.2 目标用户收敛

| 分层 | 用户 | 核心场景 | 本期是否主攻 |
|---|---|---|---|
| 主 | 考研/考证自学者，手上有大量 PDF 与网课 | 资料太多看不完 → 要能背能练 | **是** |
| 次 | 需要把课程视频转笔记的学生 | 网课记不住重点 | 是（已有优势） |
| 放弃 | 只想背单词、不要自己资料的人 | 背词书 | **否**（明确不做） |

### 1.3 不做清单（Won't，显式写死）

| 不做 | 理由 |
|---|---|
| 自建词库 / 词书 | 内容成本 ≥8 人日 + 需外部词库，与定位冲突 |
| 自建海量题库 | 粉笔/猿题库有百万级题库，硬拼无胜算 |
| 模考排名 / 社交 | 需真实用户量才有意义，当前无 |
| 插件生态 / 白板 / 多视图数据库 | 竞品护城河，投入产出比低 |
| 桌面客户端（Tauri） | 已决策暂不做 |

### 1.4 三阶段目标

| 阶段 | 主题 | 完成标志（可验收） |
|---|---|---|
| **S1（1–2 周）** | 接线 | 5 条断边接上 3 条；刷题有完整考试形态；仪表盘降到 ≤7 块 |
| **S2（3–4 周）** | 深度 | 资料详情页成为二级枢纽；掌握度统一；视频产物可导出可检索 |
| **S3（5–8 周）** | 差异化 | 学习型 AI：按薄弱点出题、针对错题讲解（竞品空白区） |

## 2. 技术层

### 2.1 技术债务清单（按危害排序）

| # | 债务 | 危害 | 证据 | 建议 |
|---|---|---|---|---|

### 2.2 技术优化方向

| 方向 | 具体做法 | 收益 | 优先级 |
|---|---|---|---|
| **接口真实性治理** | 建立「接口可用性清单」：每个接口标注 真实可用 / 空壳 / 未接线，空壳接口要么实现要么下线 | 消灭"看起来有实际没有"的坑 | **P0** |

## 3. 用户体验层

### 3.1 五条断边接线（S1 必做）

| 断边 | 现状 | 接法 | 成本 |
|---|---|---|---|
| 资料 → 笔记 | 空壳接口 + 前端未调 | 资料卡片加「生成笔记」，真实调用并进任务中心 | 3 人日 |
| 问答 → 笔记/卡 | 问答是终点 | 答案下方「存为笔记」「生成卡片」，带来源引用 | 1 人日 |
| 卡片 → 刷题 | 两表无关联 | 卡片详情加「练这道」→ 生成同知识点题目 | 2 人日 |
| 刷题 → 复习 | 掌握度不回写 | 错题「加入卡片」→ 进入复习队列 | 2 人日 |
| 查词 → 卡片 | 无单词实体 | **本期不接**（战略不做词库） | — |

### 3.2 仪表盘减负（最紧急的体验问题）

**现状**：11 个数据块，其中「今天要复习 25」重复出现 3 次（闭环条 / hero 卡 / 需要注意卡）。

| 保留（7 块上限） | 下线 / 迁移 |
|---|---|
| ① 学习闭环五步条 | 「系统与用量」整卡 → 迁到设置页（开发者指标，学习者不需要） |
| ② hero：今天要复习 N 张 | 「近 7 天作答」空态块 → 有数据才显示 |
| ③ 接下来要复习（卡包分布） | 「需要注意」重复块 → 合并进 ②的副文案 |
| ④ 四项指标带（资料/卡片/答题/正确率） | 热力图 → **<7 天数据时隐藏** |
| ⑤ 刷题背诵推荐 | 「最近资料」→ 迁到资料页 |
| ⑥ 学习热力图（有数据才显示） | 快速上传 → 保留但缩为一行入口 |
| ⑦ 快速上传（一行） | — |

**收益**：一屏数据块 11 → 6–7，符合设计系统红线；重复信息消除。

### 3.3 空态统一（现状三个空态同屏）

**问题**：笔记页左栏"还没有内容"、中栏"选一篇笔记开始"、右栏"还没有引用本文"——三个空态同时出现，全是灰字，视觉噪。

| 规则 | 做法 |
|---|---|
| 一屏最多 1 个主空态 | 中栏是主战场 → 只在中栏展示主空态；左右栏空态缩为一行提示文字 |
| 空态必须有动作 | 主空态 = 一句说明 + 1 个动作（新建笔记 / 导入题库） |
| 空态图标统一 | 用 `ICONS` 内联 SVG 40px 圆角容器，替换 Antd 默认 inbox 图标 |

### 3.4 导航与命名

| 问题 | 建议 |
|---|---|
| 左栏 12 项扁平 | 分三组：**学习**（概览/笔记/学习/复习）、**资产**（资料/卡包/视频）、**系统**（问答/任务/设置）——现状已分组，但「计划」归属不清 |
| 「文档」与「资料」含义重叠 | **统一为「资料」**，删掉「文档」入口（或改名为「解析记录」） |
| 「学习」页含刷题+背诵+测试+错题本四模式 | 命名改为「练习」，四模式改 Segmented 为「刷题 / 背诵 / 模考 / 错题」 |

### 3.5 动线优化（≤3 步原则）

| 任务 | 现状步数 | 目标 |
|---|---|---|
| 上传资料 → 看到卡片 | 3 步（资料页→上传→等解析） | 2 步（保留） |
| 复习一张卡 → 看到来源笔记 | 3 步（复习→点来源→笔记） | 已优化为 2 步（直达 `/notes?note=id`） |
| 问一道题 → 存成笔记 | **不可达** | 2 步（问答→存为笔记） |
| 做错一道题 → 变成卡片背 | **不可达** | 2 步（错题→加入卡片） |

### 4.2 审美主轴（从「堆」到「留」）

| 原则 | 现状 | 目标 |
|---|---|---|
| **一个焦点** | 多块同权重竞争眼球 | 每屏只有 1 个 hero（44px）+ 1 个主按钮 |
| **留白即层级** | 靠边框和灰底分块 | 用间距（24/32）分块，减少边框数量 |
| **纸墨质感** | 背景偏冷灰，缺层次 | 暖纸底 `#f7f4ee` + 发丝线 `rgba(31,27,22,.10)`，删除彩色阴影 |
| **颜色只表意** | 蓝色链接 + 灰标签混用 | 墨蓝仅用于「当前/关键数字」，红色只留错误 |
| **数字等宽** | 部分数字未等宽 | 全部 `tabular-nums`，时间戳用 `--mono` |

## 8. 需要你拍板的 3 件事

1. **定位是否收敛**为「资料转物料」并显式放弃词库/题库自建？（决定后续所有优先级）
2. **S1 范围**是否按「17 人日 / 4 批次」执行？若只做一半，建议优先批次一（刷题考试形态）+ 批次三（UI 减负）
3. **仪表盘减负**是否同意把「系统与用量」迁到设置页？（这是最直接的观感提升，但会让设置页变重）

> 本方案为产品设计参考，具体实施请结合公司合规与法务要求确认。
