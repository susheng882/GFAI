## 0. 口径与合规边界（先读）

1. **只借鉴交互逻辑与信息分层，不复制像素、图标、品牌文案、专有术语。**
   - 不落地：不背单词「考义 / 考点 / 考频 / 考题」四件套原词、欧路「生词笔记 / 生词卡片播放」原词、Kimi 品牌名与「Kimi 文档」界面、ima「问问 ima / 知识库广场」原词。
   - GFLC 统一中文：词条、释义、例句、发音、生词本、卡片、复习、资料、问答。
2. **不引入新视觉 token。** 所有借鉴项落到既有纸墨风格：卡片 `#fdfbf7`、发丝线、强调 `#1f4d6b`、图标走 `ICONS` 内联 SVG 18px/1.5、禁 emoji、字重仅 400/500。
3. **不声称已实现。** 表中「GFLC 是否已有」以 2026-11-23 当前代码为准（含已落地的 B4/B5/B7/B9/B10/B12 等改进，见 §1），代码里没有就写「❌ 无」。
4. **不把营销文案当功能证据。** 官方商店页、官网首页只能证明「产品宣称具备」；具体交互细节若只有第三方实测/教程，逐条标「第三方口径」。
5. 凡查不到的一律写「未查证」，不编造版本号、截图、具体页数或数据。

**优先级口径**：P0 = 当前明确短板且低成本；P1 = 本迭代可规划；P2 = 需数据模型改造或外部依赖。
**成本口径**：低 = 1–2 天前端；中 = 3–5 天含联调；高 = ≥1 周或数据模型 / 外部服务改造。

## 2. A 组 · 不背单词（语境驱动的词书流）

来源：`http://www.bbdc.cn/`（官网）、`https://m.app.mi.com/detail/70855`（小米应用商店官方页，版本 5.11.10，更新 2026-11-19）、`https://www.qh24.com/soft/649324.html`、`https://pwa.sspai.com/post/76700`（少数派实测）、`https://sspai.com/post/87587`（少数派六款横评）、`https://news.qq.com/rain/a/20230911A06GHC00`（IT 时报实测）、`https://www.18touch.com/soft/74970.html`（第三方教程）。检索日期 2026-11-23。

| 功能点 | 交互细节 | 用户价值 | GFLC 是否已有 | 借鉴优先级 |
|---|---|---|---|---|
| 原声例句（核心资产） | 官网：「海量原声例句 选自影视和新闻等真实语境」「原声例句由轻听英语全程数据支持」；商店页：「150 万+ 原声例句」「5 万+ 词组搭配」；第三方实测：例句多为美剧/英剧/电影台词与纪录片旁白，保留原剧背景音，可整句播放 | 词义锚在画面+语气上，记忆是「场景」不是「词表」 | ❌ 无。卡片只有文本 Q/A，无音频、无例句来源 | P2（内容资产重，非交互问题） |
| 词根词缀 + 派生树 | 官网：「2000+ 词根词缀，覆盖近 2 万词条」；商店页：「5500+ 派生词汇树」；第三方：点单词可按音节拆分，详情页给「前缀 + 词根 + 联想」 | 用构词法把生词挂到熟词上，降低单词语义孤立 | ❌ 无 | P2 |
| 三档自评 + 答对计数 | 第三方实测：每组 10–15 词，学完用「认识 / 模糊 / 忘记了」自评；每个词需**答对 4 次词义**才进入后续复习，中途答错重新学 | 规则透明，用户知道「怎样才算过」 | ⚠️ 部分。四档 FSRS 已有，但**无「同一词需连续答对 N 次」的判据** | P2 |
| 释义遮挡 + 盲选词义 | 第三方：先给 4 个易混选项盲选词义，选完才显示正确答案；点中文词才展开对应例句 | 先回忆再核对，避免「看着答案点头」 | ⚠️ 部分。刷题有选择题，背诵卡是「翻面」，不是「先选后证」 | P1 |
| 卡片信息结构 | 综合第三方（部分查证）：正面 = 单词 + 音标 + 发音按钮 + 场景图 + 原声例句（**释义默认遮挡**）；背面 = 词性/中文释义（考义加粗）+ 考点词组 + 词根词缀拆分 + 派生词 + 更多例句 | 正面只给「语境线索」，背面才是「知识块」；翻面动机强 | ❌ 无。现有卡正面即问题、背面即答案，无「线索层 / 知识层」分层 | **P1** |
| 拼写测试 | 官网：「智能拼写测试 学完单词动动手指强化记忆」；第三方：每组结束进入拼写，错误字母标红并播放正确读音 | 从再认进阶到产出，检验是否真会写 | ❌ 无（刷题有填空，但不由卡片词触发） | P2 |
| 查词入口 | 第三方教程：主界面**下拉**弹出单词搜索框，输入即查（**部分查证**，未见官方帮助原文） | 遇到生词可当场查，不必退出 | ❌ 无 | P1（与欧路合并看） |
| 例句内二次捕获 | 官网用户评论：「例句里面的单词还可以再收藏到单词本」（**用户评论口径，非官方功能说明**） | 读例句时顺手把下一个生词收走，捕获成本≈0 | ❌ 无 | P2 |
| 学习量「高利贷」 | 少数派：「复习的单词数量比新学的单词要多属于基本操作」；第三方：每日新词可调（建议 20–30） | 复习压力真实存在，用户需自己控量 | ⚠️ 部分。已有「复习 + 新学 = 今日」队列条，但**无「复习多则自动减新词」的配额联动** | P1 |
| 学习统计 | 第三方（低可信）：每日时长、连续天数、retention、每日新增/复习柱状图 | 看见坚持与负担趋势 | ⚠️ 部分。Dashboard 有热力图，复习侧无「新增 vs 复习」结构图 | P2 |
| 随身听 / 沉浸阅读 | 商店页与第三方：单词、释义、例句循环播放；已学词嵌入外刊短文，目标词标蓝点击查义 | 碎片时间听觉复现；在语篇中再遇 | ❌ 无 | P2（依赖音频与语料） |

> **不背单词的产品重心是「词书 + 语境」，不是「查词」**：它假设用户按词书推进，查词只是辅助。因此它在「例句真实性」上最强，在「随遇随收」上弱于欧路。

| 发音与评分 | 官方：单词/例句英音美音切换；深度学习发音打分，精确到音节；句子级评分 | 输出端纠音 | ❌ 无 | P2 |

## 7. 特别回答：GFLC 的「资料→笔记→卡片→刷题→复习」闭环，更完整还是更割裂？

### 7.1 先给结论

**模块覆盖上更完整，端到端动线上更割裂。** 准确说：**GFLC 是「唯一把五段都做出来」的产品，但不是「每一段之间都接上」的产品。**

判断依据不是「有没有这个页面」，而是**跨段是否需要用户手动搬运、切换页面或重复录入**。

### 7.2 逐段连通性核对（本轮代码实测）

| 边 | GFLC 现状 | 证据 | 判定 |
|---|---|---|---|
| 资料 → 卡片 | 上传 → 解析 → 「生成卡片」一键出章节卡包 | `DocumentsPage.jsx:40-60`；`documents.py:114-124` | ✅ 直连（且**跳过笔记**，路径更短） |
| 资料 → 笔记 | 接口存在但只写标题/摘要/要点，不生成正文；页面无入口 | `documents.py:177-188` | ❌ 断（空壳） |
| 笔记 → 卡片 | 正文 `::` 行 + 显式「同步卡片」 | `NotesPage.jsx:278-297`；`notes.py:443-448` | ⚠️ 半自动（多一步确认，但可接受） |
| 卡片 → 复习 | 到期队列、四档、间隔预览、来源回跳 | `ReviewPage.jsx:84-118` | ✅ 直连 |
| 复习 → 笔记 | 卡面「来源」直达笔记 | `ReviewPage.jsx:302-310` | ✅ 直连（竞品中少见） |
| 卡片 → 刷题 | 题库独立，`/quiz/generate` 只读 `Question` 表 | `quiz.py:152-215` | ❌ 断 |
| 刷题 → 复习 | 答题更新 `Question.mastery`，不回写 `Card` | `quiz.py:217-243` | ❌ 两套掌握度 |
| 资料/笔记 → 问答 | RAG 同时检索文档块与笔记块 | `qa.py:171-188`；`rag.py:157-182` | ✅ 直连 |
| 问答 → 笔记/卡片 | 无保存入口 | `QAPage.jsx` | ❌ 断（终点） |
| 查词 → 卡片 | 无查词 | 全库无实现 | ❌ 不存在 |

**连通率**：10 条边里 4 条直连、1 条半自动、5 条断/不存在。

### 7.3 与四个竞品对照（谁在哪一段更强）

| 维度 | 不背单词 | 欧路词典 | Kimi | ima | GFLC |
|---|---|---|---|---|---|
| 遇到生词 → 收下 | 弱（词书驱动，查词是辅助） | **强（0 次切页，一键入本）** | 无此概念 | 无此概念 | ❌ 无 |
| 收下 → 复习 | 强（词书内自动排） | 强（生词本直接卡片播放） | 无 | 无 | 强（FSRS + 四档 + 间隔可见） |
| 资料 → 结构化产物 | 无 | 无 | **强（URL/视频→文档，可导出）** | 强（摘要→笔记→入库） | 中（资料→卡片强，资料→笔记弱） |
| 产物 → 提问 | 无 | 无 | 强（会话追问） | **强（@知识库 + 原文引用）** | 强（RAG + 来源芯片） |
| 提问 → 记忆/复习 | 无 | 无 | 无 | 无（小测验一次性） | ❌ 断 |
| 跨段手动搬运 | 中 | **低** | 高（靠复制/导出） | 低 | **中高（4 处断点）** |

### 7.4 结论的三条依据

1. **完整性来自「段」的齐全，不来自「链」的顺畅。** 四个竞品各自只覆盖 2–3 段（单词类覆盖「收→复习」，AI 笔记类覆盖「资料→笔记→问答」），GFLC 五段全有，所以「更完整」成立。
2. **割裂感来自三个「单向终点」**：问答答完不能存、刷题与卡片互不回写、资料不能直接变笔记。用户每遇到一个终点，就要么复制粘贴，要么回另一个模块重建——这正是 ima/Kimi 用「侧栏 AI + 一键入库/导出」消掉的动作。
3. **单词场景是「整段缺失」而非「一段割裂」**：GFLC 没有词实体与查词入口，所以「遇到生词」这一步根本不发生在 GFLC 内；这不是链路不顺，是链路起点不在产品里。**这一条比任何 UI 优化都更值得先决策**（做 / 不做单词场景）。

### 7.5 建议的取舍（给主线程）

- **若定位是「通用学习工作台」**：不追单词词库，优先补 #7（资料→笔记）、#8（问答→笔记/卡）、#6（配额联动）三条低成本边，把「五段」变成「五段连成环」，收益最大。
- **若定位要覆盖英语备考**：必须先做 #1 + #2 + #3（词实体、查词、卡片分层），否则做多少 UI 都只是「问答卡换皮」；#4/#5 可以后置。
- **不建议**为了「像 ima」而新开一个资料阅读器：GFLC 已有资料页与问答页，补「侧栏摘要 + 生成笔记」即可，避免第三套阅读界面。

### 10.2 核心结论（5 条）

1. **GFLC 缺的不是「背单词页」，而是「词」这一层实体与「查词」这个入口。** 没有词条字段（音标/释义/例句/音频/词根），单词场景只能退化成通用问答卡；这是产品范围决策，不是 UI 任务。
2. **单词类的最短动线是欧路：查词 → 一键入生词本 → 卡片播放，0 次页面切换。** 不背单词强在例句真实性与卡片分层（正面线索、背面知识块），弱在「随遇随收」；两者可分别借鉴「动线」与「信息结构」。
3. **AI 笔记类的分野在「AI 的位置」：ima 把 AI 放在当前内容的侧栏，Kimi 整个界面就是对话。** GFLC 笔记页已经是侧栏形态（对齐 ima），但资料页与问答页仍是「跳出去问」，这是最直观的割裂感来源。
4. **闭环判断：覆盖更完整，动线更割裂。** 10 条边里 4 条直连、1 条半自动、5 条断（资料→笔记、卡片→刷题、刷题→复习、问答→笔记/卡、查词→卡）。先把 3 条低成本边接上（问答存笔记/卡、资料生成笔记、新词复习配额联动），比新增页面收益大。
5. **最值得抄的不是功能，是「沉淀动作」**：ima 的「答案→笔记→知识库」与 Kimi 的「产物→可编辑文件」都在解决同一件事——让 AI 的输出有下一站。GFLC 的问答目前是终点，这是投入产出比最高的一处修补。
